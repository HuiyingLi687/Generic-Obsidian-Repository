# Generic-Obsidian-Repository

> 通用项目内容知识库 + 单个项目文档库。
> **给 AI 的话：不要从文件列表开始读，按下面第一节的顺序读，前三步约两屏。**
> 最后更新：2026-11-02

---

## 一、AI 先读什么（顺序固定，不要跳）

| 顺序 | 读这个 | 读完你应该知道 |
|---|---|---|
| **1** | 本文件 | 仓库怎么组织、东西去哪找 |
| **2** | [当前进度](02云云天平/00当前进度/当前进度.md) | 现在做到哪、下一步、**什么绝对不能动** |
| **3** | [00数据库总览](02云云天平/02软件架构/02数据库/00数据库总览.md) + [01表归属矩阵](02云云天平/02软件架构/02数据库/01表归属矩阵.md) | 库在哪、改一张表会波及哪些服务 |
| **4** | [00需求索引](02云云天平/01功能需求/00需求索引.md) | 有哪些需求、哪些还没做 |
| **5** | `02云云天平/03业务模块/<相关模块>/` | 具体接口字段、页面结构、变更点 |

第 5 步**只在真要改某个模块时才展开**。不要一次把 54 个 md 全读进来。

> ⚠️ 第 2 步的「约束（AI 不要做）」小节优先级高于任何文档：里面写的是不能碰的生产库地址和历史脚本。
> **没读「当前进度」就动手改文档或写代码，是错的。**

需要写代码时再额外读：`00当前仓库规范/` 下的三份规范（见第四节）。

## 四、硬约束（违反就是错）

1. **返回体全局统一 `Result<T>`**（`code / msg / data / traceId`），见 [错误码和统一返回体](00当前仓库规范/编码规范/错误码规范/错误码和统一返回体.md)
2. **接口变更文档跟接口设计放一起**，不进 `01功能需求/`
3. **项目内的旧版本进项目自己的 `99归档/`**，不进顶层 `99归档/`
4. **只影响单个模块的方案留在模块目录**，影响多模块的才上提到 `02软件架构/`
5. **不要假设「代码提交了 = 数据库改了」**，这两件事在本项目里是分开的，改表必须同时登记台账
6. **不要直连生产库执行 DDL / UPDATE**，生产库地址见「当前进度」的环境表

## 五、脚本（双击即可）

| 文件 | 作用 |
|---|---|
| `push-all.bat` | 提交并推送全部改动到 GitHub。无改动会跳过；推送失败自动 `pull --rebase` 重试；冲突即停 |
| `检查链接.bat` | 全库链接体检。报告断链并反查「原名改成了什么」，`python tools/linkcheck.py --fix` 可自动修复 |

## 六、维护规则

- **改名、移动文件请在 Obsidian 里做**（右键 → 重命名）。在资源管理器 / git / 脚本里改名，`[文本](相对路径.md)` 这种相对路径链接必断，改名后跑一次 `检查链接.bat`
- **新增项目**从 `03` 开始编号，一个项目一个号，不复用已删编号
- **新文件命名带两级序号**：目录级 `00/01/02`，文件级同前缀，保证排序稳定
- **顶层没有需求暂存区**（`01通用/` 已废弃待删）。需求直接写进项目的 `01功能需求/`，别在顶层新建 `01功能需求`
