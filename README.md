# Generic-Obsidian-Repository

> 通用项目知识库 + 多项目文档库。**一个仓库装多个项目**，每个项目一个编号目录，项目之间互不干扰。
> **给 AI 的话：不要从文件列表开始读。按第一节的顺序读，先确定「这次是哪个项目」。**
> 最后更新：2026-11-02

---

## 一、AI 先读什么（顺序固定，不要跳）

| 顺序 | 读什么 | 读完你应该知道 |
|---|---|---|
| **1** | 本文件 | 有哪些项目、每个项目在哪、仓库级规矩是什么 |
| **2** | `<项目>/README.md`（项目卡） | 这个项目是什么、技术栈、模块清单、项目级约束 |
| **3** | `<项目>/00当前进度/当前进度.md` | 现在做到哪、下一步、**什么绝对不能动** |
| **4** | `<项目>/01功能需求/00需求索引.md` | 有哪些需求、哪些还没做 |
| **5** | `<项目>/02软件架构/02数据库/` | 只在**要动数据**时读：库在哪、改一张表波及谁 |
| **6** | `<项目>/03业务模块/<相关模块>/` | 只在**真要改某个模块**时才展开 |

- 前三步约两屏。**没读「当前进度」就动手改文档或写代码，是错的。**
- 第 3 步里的「约束 / AI 不要做」小节，优先级高于任何其他文档（通常写的是不能碰的生产库、历史脚本）。
- **不知道去哪个项目？** 看第二节的编号登记表。项目目录名 = 编号 + 项目名，如 `02云云天平`。

## 二、顶层目录与编号

| 编号 | 用途 | 现状 |
|---|---|---|
| `00` | **仓库规范**：所有项目通用，约束性文档 | `00当前仓库规范/` |
| `01` | **需求暂存区**：还没想好归哪个项目的碎片，7 天内转正或删 | 当前是 `01通用/`，空；规范已判「待删」 |
| `02–09` | **项目**，一个项目一个号，按建立顺序占用 | `02` 云云天平 |
| `10–89` | 预留：知识库、素材库、脚本库 | 未启用 |
| `99` | 归档：**整个项目终结后**整体搬进来 | 空 |

```
Generic-Obsidian-Repository/
├── 00当前仓库规范/       所有项目通用的规范，必须遵守
├── 01通用/               需求暂存区（当前空，待删）
├── 02云云天平/           第 1 个项目：汉考宝
├── 99归档/               项目结项后的归宿
├── tools/                仓库自用脚本（不属于任何项目）
├── push-all.bat          提交并推送
├── 检查链接.bat          全库链接体检
└── .obsidian/            配置，不要手改
```

**编号规则**：新项目从 `03` 往后续，**不复用已删除的编号**。编号只代表建立时间，不代表重要性。

## 三、每个项目内部的标准结构

所有项目长同一个样：按「**定位 → 全局 → 模块**」三层分，**不是按文档类型分**。

```
<编号><项目名>/
├── README.md                项目卡：唯一入口，AI 第一读
├── 00当前进度/
│   ├── 当前进度.md           活文档：现在到哪，AI 第二读
│   ├── 00当前进度模板.md
│   └── 00数据库变更台账/      按月，编号倒序（越小越新）
├── 01功能需求/               要做什么
│   ├── 00需求索引.md         需求清单 + 优先级 + 状态
│   └── 00功能点模板.md
├── 02软件架构/               怎么做
│   ├── 01架构总览/           服务划分、技术栈、部署拓扑
│   ├── 02数据库/             库在哪、表归属、变更台账
│   ├── 03数据字典/           枚举、字典表
│   └── 04关键算法/           跨模块的机制与算法
├── 03业务模块/               文档大头在这，按模块分
│   └── <模块名>/
├── 90素材/                   粘贴的截图与插图，插件统一落点
└── 99归档/                   项目内被取代的旧版本
```

### 每个目录回答什么问题

判断一篇文档该放哪，只问一句：**它主要在回答哪个问题？** 不要问「它是什么类型」。

| 它回答的问题 | 放哪 |
|---|---|
| 这个项目是什么、怎么上手 | `README.md` |
| 现在做到哪、下一步干什么 | `00当前进度/当前进度.md` |
| 某个字段什么时候加的 | `00当前进度/00数据库变更台账/` |
| 要做成什么样、怎么算做完 | `01功能需求/` |
| 系统怎么搭、表怎么设计、跨模块怎么协作 | `02软件架构/` |
| 某个模块的接口字段、页面结构、变更点 | `03业务模块/<模块>/` |
| 原型、导出件、数据样本 | `90素材/` 或模块目录内 |
| 已被取代的旧版本 | 项目自己的 `99归档/` |

几个容易放错的地方：

- **接口变更文档跟接口设计放一起**，不进 `01功能需求/`
- **只影响单个模块的方案留在模块目录**，影响多模块的才上提到 `02软件架构/`
- **项目内的旧版本进项目自己的 `99归档/`**，不进顶层 `99归档/`（顶层只收整个项目结项后的搬迁）

> ⚠️ 各项目实际目录可能与上面有个别偏差，**以该项目 `README.md` 里写的路径为准**。

## 五、硬约束

### 仓库级（所有项目都适用）

1. **改名、移动文件在 Obsidian 里做**（右键 → 重命名）。在资源管理器 / git / 脚本里改名，`[文本](相对路径.md)` 这种相对路径链接必断。改完跑一次 `检查链接.bat`
2. **编号不复用**。项目删了编号就空着，新项目往后续
3. **新文件命名带两级序号**：目录级 `00/01/02`，文件级同前缀，保证排序稳定
4. **跨项目通用**的规范才进 `00当前仓库规范/`；项目独有的写进项目卡
5. **代码提交 ≠ 数据库改了**。任何改表操作必须同时登记项目自己的变更台账

### 项目级

各项目自己的技术约束写在 `<项目>/README.md` 的「关键约束」里，不在本文件重复。
例：汉考宝要求返回体统一 `Result<T>`、11 个服务共用一个库 —— 这些只在那个项目成立。

## 六、新建一个项目

1. 从 `03` 起取下一个空编号，建目录 `<编号><项目名>/`
2. 按**第三节的结构**建子目录（照抄，一个不缺）
3. 写 `README.md` 项目卡，至少包含：是什么 / 技术栈 / 模块清单 / 关键约束 / 文档地图
4. 写 `00当前进度/当前进度.md`，第一节就写「下一步」
5. 在**第四节的项目清单**里加一行

> 模板文件不用重新写：把 `02云云天平/00当前进度/`、`01功能需求/` 里的 `00*模板.md` 复制过去，改项目名即可。

## 七、脚本（双击即可）

| 文件 | 作用 |
|---|---|
| `push-all.bat` | 提交并推送全部改动。无改动跳过；推送失败自动 `pull --rebase` 重试；冲突即停 |
| `检查链接.bat` | 全库链接体检。报告断链并反查「原名改成了什么」；`python tools/linkcheck.py --fix` 自动修复 |

两个脚本都作用于**整个仓库**（所有项目一起），不用分项目跑。

## 八、维护规则

- **本文件只在「结构或规则变了」时改**：新增项目、新增规范、编号规则调整。日常进度一律写进各项目的 `当前进度.md`
- **看不懂某篇文档该放哪**，先读 [Obsidian管理规范](00当前仓库规范/流程规范/Obsidian管理规范.md) 第三节，再决定
- **空目录不要留**。规划了但没内容的目录，要么先放一份模板，要么先别建 —— 空目录会让 AI 以为那里该有东西
