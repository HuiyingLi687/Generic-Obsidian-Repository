# 写字课「笔顺规则页」前端动态渲染指南

> **适用接口**：`GET /course/writing/catalog`（取其中的 `ruleSections`）。
> **目的**：前端不要再把规则 / 标签 / 颜色写死，改为**完全消费后端返回的数据**，动态还原 UI。
> **字段口径**以 `写字课-接口设计文档.md` §3.2.1 为准；本文只讲「前端怎么用」。

---

## 0. 一句话结论

后端已经把「区块顺序、卡片分组、标签文案、标签位置、标签颜色、例字与例字 id」**全部算好放在 `data.ruleSections` 里**了。前端只要做三件事：

1. **拉一次 `catalog` 存进本地**（IndexedDB），靠 `dataVersion` 判失效；
2. **遍历 `ruleSections`** 渲染区块，区块内按 `groupCode` 把多行合并成卡片；
3. **按 `tags[].style / position / bgColor / fgColor`** 渲染每个标签，例字按 `exampleCharIds` 点击跳详情。

---

## 1. 请求与缓存

```ts
// 1) 拉取（笔顺规则页只用到 ruleSections，但 catalog 一次把笔画+规则都返回）
const res = await fetch('/course/writing/catalog', {
  headers: { 'Accept-Language': 'zh' }, // zh / en / vi
});
const { code, data } = await res.json();

// 2) 缓存 + 版本失效
const local = idb.get('writing_catalog');
if (local && local.dataVersion === data.dataVersion) {
  renderRules(local.ruleSections);   // 版本没变，直接用缓存
} else {
  idb.set('writing_catalog', data);
  renderRules(data.ruleSections);    // 版本变了，重新渲染
}
```

**关键点**：
- `dataVersion` 是 `long`，比对用 **`!==`**（不要用 `>`，也别拿时间戳比）。服务端保证「内容变了就 bump 这个号」，前端只认「相等 / 不等」。
- 缓存存**整份 `data`**（含 `dataVersion`），不要只存 `ruleSections` —— 否则下次无法比版本。

## 2. 三层结构：`ruleSections` → 区块 → 卡片（行按 `groupCode` 合并）

后端返回的规则数据是**三层**，别跳层：

```
ruleSections[]               —— 4 个区块，顺序恒定（BASIC→STRUCT→CHAR_TIP→MOTTO）
  └─ rows[]                  —— 原始行，不合并；同组多行都返回
        groupCode            —— 分组键：同组多行值相同，前端按它合并成一张卡片
        tags[]               —— 该行自己的标签（见 §3）
        examples / exampleCharIds / description / title / sortOrder / mediaUrl
```

### 2.1 区块（section）

```ts
// ruleSections 固定 4 个、顺序固定，区块标题后端给空、前端走 i18n 字典
const RULE_TYPE_LABEL = {
  BASIC:      i18n.t('writing.rule.basic'),     // 「基本笔顺规则」
  STRUCT:     i18n.t('writing.rule.struct'),    // 「特殊结构笔顺」
  CHAR_TIP:   i18n.t('writing.rule.charTip'),   // 「高频易错字提醒」
  MOTTO:      i18n.t('writing.rule.motto'),     // 「一句话口诀」
};

data.ruleSections.forEach(section => {
  renderSection(RULE_TYPE_LABEL[section.ruleType], section);
});
```

**⚠️ 顺序不要自己排**：直接按 `ruleSections` 数组下标渲染，后端已按枚举声明顺序排好。**`cardCount`（共 N 条）是服务端按 `groupCode` 去重算好的**，不要拿 `rows.length` 当条数 —— 半包围结构 3 行只算 1 条，`rows.length` 会多算。

### 2.2 卡片（按 `groupCode` 合并行）

```ts
function groupRows(rows) {
  // 按 groupCode 分组；同组多行 = 一张卡片的多个「子块」
  const map = new Map();
  for (const row of rows) {
    if (!map.has(row.groupCode)) map.set(row.groupCode, []);
    map.get(row.groupCode).push(row);
  }
  return [...map.values()]; // 保持首次出现顺序
}

const cards = groupRows(section.rows);
cards.forEach(rowsInCard => {
  // rowsInCard.length === 1 → 单行卡片
  // rowsInCard.length > 1  → 多行卡片（「半包围结构」拆 3 子块、「点的位置区分」拆 2 子块）
  renderCard(rowsInCard);
});
```

**卡片内部**：
- **卡片标题**取 `rowsInCard[0].title`（同组多行 `title` 相同，取第一个即可；后端已按语言回退）。
- **每个子块**（每行）各自渲染自己的 `description` + `tags` + `examples`。
- 子块顺序：后端已按 `sortOrder`、再按 `id` 升序排好，前端直接按数组顺序渲染。

## 3. 标签渲染：`tags[].style / position / bgColor / fgColor`

这是「别写死」的核心。标签有**三个维度**，必须组合着用：

| 维度 | 字段 | 含义 |
|---|---|---|
| **贴哪** | `position` | 7 个锚点（见下表） |
| **什么样式** | `style` | `BADGE` 徽章 / `HINT` 灰字 / `PLAIN` 正文 |
| **什么颜色** | `bgColor` + `fgColor` | 十六进制色值（无 `#`），徽章/灰字靠它区分深浅 |

### 3.1 `position` 的 7 个锚点（决定渲染到哪一层、哪个位置）

| 值 | 层级 | 渲染位置 |
|---|---|---|
| `RULE_TYPE_LEFT` | 区块级 | 区块标题左侧 |
| `RULE_TYPE_RIGHT` | 区块级 | 区块标题右侧（如「8 条」「高频易错」「7 字」） |
| `TITLE_LEFT` | 卡片级 | 卡片标题左侧 |
| `TITLE_RIGHT` | 卡片级 | 卡片标题右侧（如「按包围方向分三情况」） |
| `CARD_CORNER` | 卡片级 | 卡片右上角 |
| `DESCRIPTION_LEFT` | 行级 | 说明文字左侧（如「左上包围 厂·广·尸」） |
| `DESCRIPTION_RIGHT` | 行级 | 说明文字右侧（如「极易错」） |

**合并取值规则**（后端已按此约定放数据，前端照做即可）：
- 区块级标签（`RULE_TYPE_*`）落在**该区块 `sortOrder` 最小的那一行**；
- 卡片级标签（`TITLE_*` / `CARD_CORNER`）落在**组内 `sortOrder` 最小的那一行**；
- 行级标签（`DESCRIPTION_*`）**每行各自拥有**。

前端**不要**去重或只取第一行 —— 后端已把标签放在正确的那一行上，前端遍历每个 `row.tags` 按其 `position` 贴到对应位置即可。

### 3.2 `style` + 颜色（决定长什么样）

```ts
function tagStyle(tag) {
  const css = {};
  if (tag.fgColor) css.color = `#${tag.fgColor}`;
  if (tag.bgColor) css.backgroundColor = `#${tag.bgColor}`;
  return css;
}
```

**三种 style 的渲染规则**：

| style | 外观 | bgColor | fgColor |
|---|---|---|---|
| `BADGE` | 圆角胶囊徽章（带底色） | **有** | **有** |
| `HINT` | 灰色提示小字（无底色） | 无 | **有**（深灰 `6C727E` / 浅灰 `9CA3AF`） |
| `PLAIN` | 普通正文，与说明同色 | 无 | 无 |

**当前设计稿里的徽章三类视觉**（供前端对照，但**逻辑上别写死**——直接读 `bgColor`/`fgColor`，将来运营加新颜色前端零改动）：

| 视觉 | bgColor | fgColor | 出现处 |
|---|---|---|---|
| 粉底红字 | `FDECEC` | `D32F2F` | 「8 条」「高频易错」「7 字」「先写点」「左上包围 厂·广·尸」 |
| 琥珀底琥珀字 | `FFF7E8` | `D9A21B` | 「极易错」 |
| 深红底反白 | `D32F2F` | `FFFFFF` | 「左下包围 辶·廴」 |
| 深灰提示字 | — | `6C727E` | 「半包围」「全包围」「按包围方向分三情况」 |
| 浅灰提示字 | — | `9CA3AF` | 「不是先写两边」「先折后撇」 |

**⚠️ 前端防御**：
- `style` 缺省（`null`/空串）→ 按 `PLAIN` 渲染（后端已兜底回填 `PLAIN`，前端再兜一层）。
- `bgColor`/`fgColor` 可能缺省（`PLAIN` 两色都不下发；`HINT` 只下发 `fgColor`）→ 缺省就**不设对应 CSS**，别给默认色。
- `tags` 可能是空数组 `[]`（不是 `null`），别直接 `.map` 崩掉。

### 3.3 标签渲染伪代码

```tsx
function renderTags(row) {
  const tags = row.tags ?? [];
  const left   = tags.filter(t => t.position.endsWith('_LEFT'));
  const right  = tags.filter(t => t.position.endsWith('_RIGHT'));
  const corner = tags.filter(t => t.position === 'CARD_CORNER');
  return (
    <>
      <span class="tag-left">{left.map(renderTag)}</span>
      <span class="desc">{row.description}</span>
      <span class="tag-right">{right.map(renderTag)}</span>
      <span class="tag-corner">{corner.map(renderTag)}</span>
    </>
  );
}

function renderTag(tag) {
  const cls = tag.style === 'BADGE' ? 'badge'
            : tag.style === 'HINT'  ? 'hint'
            : 'plain'; // PLAIN / 缺省
  return <span class={cls} style={tagStyle(tag)}>{tag.text}</span>;
}
```

> 建议前端保留 `badge` / `hint` / `plain` 三个类名做基础样式（圆角、字号、内边距），颜色全走内联 `style`（来自 `bgColor`/`fgColor`）。这样「加颜色」=「改数据」，不用发版。

## 4. 例字渲染：`examples` + `exampleCharIds` 对齐，点击跳详情

规则卡片里的例字，是两个数组**同下标一一对应**：

| 字段 | 说明 |
|---|---|
| `examples` | 英文逗号分隔的**人读副本**（如 `"十,干,丰"`），前端拆成字格展示 |
| `exampleCharIds` | 例字 id 数组（如 `[105,106,124]`），**为准**，点击例字用它跳详情 |

```ts
function renderExamples(row) {
  const chars = (row.examples ?? '').split(',').map(s => s.trim()).filter(Boolean);
  const ids = row.exampleCharIds ?? [];
  // ⚠️ 同下标对应：第 i 个字对应 ids[i]
  return chars.map((ch, i) => (
    <span class="char-cell" onClick={() => openCharDetail(ids[i])}>{ch}</span>
  ));
}

async function openCharDetail(charId) {
  // 例字详情走 /course/writing/chars?ids=<charId>（拿 stroke_paths / guide_svg 做描红演示）
  const res = await fetch(`/course/writing/chars?ids=${charId}`);
  // ... 播放笔顺动画
}
```

**⚠️ 边界**：
- `examples` / `exampleCharIds` 都可能为 `null`（CHAR_TIP 的 7 个字**不可点**，没有例字块，两字段都是 `null`）→ 渲染前判空，`null` 就不渲染例字区。
- 后端已保证「`examples` 字数 == `exampleCharIds` 长度」，前端仍建议**按下标取、不越界**（`ids[i]` 越界就不绑点击）。
- 例字描红动画数据（`stroke_paths`/`guide_svg`）在 `/chars` 接口，**不在 catalog 里**（catalog 刻意不含这些 MB 级数据）。

## 5. 完整示例（React 伪代码）

```tsx
function WritingRulePage() {
  const data = useCatalog(); // 拉取 + dataVersion 缓存（见 §1）
  return (
    <div>
      {data.ruleSections.map(section => (
        <Section key={section.ruleType}
                 title={RULE_TYPE_LABEL[section.ruleType]}
                 count={section.cardCount}
                 sectionTags={sectionLevelTags(section)}>
          {groupRows(section.rows).map((rowsInCard, i) => (
            <Card key={i} title={rowsInCard[0].title} cardTags={cardLevelTags(rowsInCard)}>
              {rowsInCard.map(row => (
                <SubBlock key={row.id}>
                  <Tags tags={row.tags} positions={['DESCRIPTION_LEFT']} />
                  <span>{row.description}</span>
                  <Tags tags={row.tags} positions={['DESCRIPTION_RIGHT']} />
                  <Examples examples={row.examples} ids={row.exampleCharIds} />
                </SubBlock>
              ))}
            </Card>
          ))}
        </Section>
      ))}
    </div>
  );
}

// 区块级标签：取该区块 sortOrder 最小的行
function sectionLevelTags(section) {
  const first = section.rows.slice().sort((a, b) => a.sortOrder - b.sortOrder)[0];
  return (first?.tags ?? []).filter(t => t.position.startsWith('RULE_TYPE_'));
}

// 卡片级标签：取组内 sortOrder 最小的行
function cardLevelTags(rowsInCard) {
  const first = rowsInCard.slice().sort((a, b) => a.sortOrder - b.sortOrder)[0];
  return (first?.tags ?? []).filter(t => t.position.startsWith('TITLE_') || t.position === 'CARD_CORNER');
}
```

## 6. 前端「别再写死」检查清单

- [ ] 区块顺序：按 `ruleSections` 数组顺序渲染，不写死 4 个区块。
- [ ] 「共 N 条」：用 `cardCount`，不数 `rows.length`。
- [ ] 卡片分组：按 `groupCode` 合并，不假设「一行一卡」。
- [ ] 标签文案：用 `tags[].text`，不写死「高频易错」这类字。
- [ ] 标签位置：用 `tags[].position`，不写死「贴在标题右」。
- [ ] 标签颜色：用 `tags[].bgColor` / `fgColor` 拼内联样式，不写死 `#FDECEC`。
- [ ] 例字：用 `examples` 拆字格、`exampleCharIds` 绑点击；判空处理 `null`。
- [ ] 缓存：认 `dataVersion !==` 判失效，不用时间戳 / `>`。
- [ ] 多语言：区块名走 i18n 字典；`title` / `description` / `tags[].text` 用后端回退好的值，前端不做翻译。
