# 题库 Excel 上传格式校验规范（上传前自查）

> **适用范围**：`POST /question/upload/hsk`、`/question/upload/csca`、`/question/upload/speaking` 三个上传接口的 Excel 交付件。
>
> **与《HSK题库数据-统一检查点与验收标准》的分工**：
> 那份管「**入库后数据对不对**」（45 个检查点 + 库侧 SQL + 验收报告）；
> 本文管「**文件能不能上传、传上去会变成什么样**」。两者不重复，先过本文再进那份。
>
> 本文是规范，不是某批数据的核查记录。任何人拿到一批 Excel，按本文逐条判定即可。

---

## 0. 一句话结论

**Excel 里怎么写不重要，重要的是上传那一刻会被改写。** 三件事必须提前知道：

1. **全角标点被强制转半角**（`，`→`,`、`。`→`.`、`……`→`..`），发生在**校验之前**，无法用 Excel 规避；
2. **16 列以外的列被静默丢弃**（常见第 17 列「图片名称」全丢）；
3. **`等级*` 表头带星号但代码不校验**，漏填不报错，会写出永远取不到的卷。

自查就三件事：列头是 16 列、9 个真必填不为空、标点接受被改写的预期。

## 1. 上传链路（理解"会变成什么样"的前提）

```
POST /question/upload/{hsk|csca|speaking}
  └─ QuestionController.doHandleExcelUpload
       └─ validateExcelResult
            └─ EasyExcel.read(...) + QuestionExcelTemplate.invoke()   ← 逐行
                 ① PunctuationConvertUtil.convertObject(data)         ← 改写在这里
                 ② ExcelValidateUtil.validateRequiredFields(data)     ← 校验看到的是已改写值
                 ③ validateSpecial(...)                               ← 子类差异校验
                 ④ transferDataMapping(...) → 落库
```

🔴 **① 在 ② 之前**，这个顺序决定了三件事：

| 现象 | 原因 | 该不该管 |
|---|---|---|
| 单元格只填了全角空格 `　` | 先转成半角空格，`trim()` 判空 → 报「不能为空」 | 符合预期，补内容即可 |
| 选项用全角冒号 `A：苹果` | 先转成 `A:苹果`，`OptionParseUtil` 只认半角，**此时能解析** | 能传，但见 §2.4 |
| 答案里句中的中文逗号 `他说，好` | 先转成 `他说,好`，再被 `split(",")` 当多答案分隔符 | 🔴 **会坏事**，见 §4.2 |

代码位置：`manage/src/main/java/com/hsktreasure/manage/check/excel/QuestionExcelTemplate.java:77`。

## 2. 标点：全角 → 半角

### 2.1 会改语义的 6 类（🔴 高危）

`PunctuationConvertUtil` 的映射表里，以下几条不是"换个样子"，而是**改了意思**：

| 原文 | 变成 | 后果 | 例子 |
|---|---|---|---|
| `…` | `.` | 省略号塌成点，`……` 一定变 `..` | `他想……` → `他想..` |
| `·` | `.` | 人名/书名间隔号错位 | `阿·Q正传` → `阿.Q正传` |
| `—` `─` `━` | `-` | 破折号变连字符，句子结构可读性下降 | `他说—算了` → `他说-算了` |
| `〈` `〉` | `<` `>` | 🔴 **生成尖括号**，前端当 HTML 标签解析，内容被吞 | `〈试行〉` → `<试行>`，页面空白 |
| `“` `”` | `"` | 左右引号塌成同一个 ASCII 引号，成对信息丢失 | `他说“好”` → `他说"好"` |
| `【` `】` | `[` `]` | 中文方括号变英文方括号 | `【答案】` → `[答案]` |

> 🔴 `〈` `〉` → `<` `>` 是唯一会**破坏渲染**的一条。正文里出现书名号套尖括号的写法（如古籍引文），上传后前端会当成未闭合标签，后面整段不显示。

### 2.2 常规转换（外观变化，语义不变）

| 类别 | 原字符 → 结果 |
|---|---|
| 句读 | `，`→`,`　`。`→`.`　`！`→`!`　`？`→`?`　`；`→`;`　`：`→`:` |
| 括号 | `（`→`(`　`）`→`)` |
| 引号 | `‘` `’`→`'`　`〝` `〞`→`"` |
| 空白 | 全角空格 `　`→ 半角空格 |
| 全角符号（22 个） | `％`→`%`　`＃`→`#`　`＄`→`$`　`＆`→`&`　`＊`→`*`　`＋`→`+`　`－`→`-`　`／`→`/`　`＝`→`=`　`＜`→`<`　`＞`→`>`　`＼`→`\`　`＾`→`^`　`＿`→`_`　`｀`→`` ` ``　`｛`→`{`　`｝`→`}`　`｜`→`|`　`～`→`~`　`＂`→`"`　`＇`→`'` |
| **不变** | `《` `》`　`「` `」`　`『` `』`　`〔` `〕`（映射表里写的是自身，等于不转） |

### 2.3 实测：改完长这样

TEST 库真实记录（`reading_match`，HSK2.0 一级）：

```
<p>Nǐ hǎo, wǒ néng chī yí kuàir ma?</p><p>你好,我能吃一块儿吗?</p>
```

原文是「你好**，**我能吃一块儿吗**？**」。拼音行本来就是半角，中文行被整体英文化。

全库 13,524 题的**残留**中文标点分布（说明后来有后处理还原过一部分）：

| 版本 | 题量 | `passage` 含中文标点 | `content` | `answer` |
|---|---:|---:|---:|---:|
| HSK2.0 | 10,561 | 2,469 | 398 | 29 |
| CSCA | 1,904 | 1,257 | 49 | 36 |
| HSK3.0 | 1,059 | 274 | 36 | 15 |

> 注意：这批残留是**历史数据 + 后处理还原**的结果，不代表新导入不会被转。**新导入 100% 会被转**。

### 2.4 三种应对，选一种

| 策略 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A. 接受半角**（建议） | 正文就按半角标点写，中文排版靠前端 CSS（字距、字体）而不是全角标点 | 无 | 与库里已有 9,000+ 题保持一致 |
| **B. 上传后还原** | 按字段把 `.` `,` `?` 还原成 `。，？` | 会误伤小数（`2.08`）、英文缩写（`Mr.`）、答案分隔符（`A,B`）→ 只能对 `passage`/`content` 做，且要白名单 | 只对阅读长文、写作材料 |
| **C. 改链路** | 在 `PunctuationConvertUtil` 加开关或白名单，只转**分隔符**不转正文 | 改 `common` 工具 + 3 个 listener，要回归三个上传接口 | 长期方案，一次性成本 |

> 🔴 不要用「改 Excel 写全角」来绕 —— 转换点在校验之前，Excel 侧无法规避。判「Excel 不合格」之前，
> 先确认是不是这条链路造成的（这是最容易被误判的一条）。

## 3. 列结构（16 列，顺序固定）

列头必须与下表**字面量完全一致**（含 `*` 和括号），顺序也一致。权威来源是 `QuestionExcelEo` 上 16 个 `@ExcelProperty`。

| # | 列头 | 必填 | 落库 | 写法 / 易错点 |
|--:|---|---|---|---|
| 1 | `考试大纲*` | ✅ | `exam_paper.version` | `HSK2.0` / `HSK3.0` / `CSCA` |
| 2 | `学科类型(HSK非必填)` | ✕ | `exam_paper.subject_type` | **HSK 整列留空**；填了会被当学科筛选条件 |
| 3 | `题型*` | ✅ | `question.type_id` | 中文名，见验收文档 §2.4 |
| 4 | `一级标题*` | ✅ | `question.title1_number` | **整数**（`1`/`2`/`3`），填「一」会解析异常 |
| 5 | `一级标题内容*` | ✅ | → `section_mapping` | 只能 `听力`/`阅读`/`书写` |
| 6 | `部分标题*` | ✅ | `question.section` | 模块内第几部分，`1..N` |
| 7 | `题目分组(或者范围)*` | ✅ | `question.question_group` | **必须 `起-止`**，如 `1-5` |
| 8 | `部分标题内容` | ✕ | `question.section_title` | 该部分指导语 |
| 9 | `题目序号` | ✕ | `question.number` | **空 = 分组行**，非空 = 单题行 |
| 10 | `题目标题` | ✕ | `question.content` | 小题干；分组行用 `---` 拆 |
| 11 | `题目内容` | ✕ | `question.passage` | 材料正文；分组行用 `---` 拆 |
| 12 | `题目选项` | ✕ | `question.option_content` | `A:..,B:..` → JSON；见 §4.3 |
| 13 | `答案*` | ✅ | `question.answer` | 选择题填选项键；分组行用 `,` 拆 |
| 14 | `分值*` | ✅ | `question.score` | varchar；分组行用 `,` 拆；见 §4.4 |
| 15 | `来源*` | ✅ | `exam_paper.source` | 卷唯一标识，≤40 字符 |
| 16 | `等级*` | ⚠️ | `exam_paper.level` | `1`~`6` 或 `7-9`；**代码不校验，见 §3.1** |

### 3.0 三条列级陷阱

1. 🔴 **第 17 列静默丢弃**：交付件常带「图片名称」列，EO 只映射前 16 列，**一个值都不会入库**。图片必须已用 `<img src="...">` 内联进 `题目内容` / `题目选项`。
2. 🔴 **字段名反直觉**：`题目标题`→`content`，`题目内容`→`passage`。别按字面猜。
3. ⚠️ **`学科类型` 不是 HSK 字段**：表头写着「HSK非必填」，HSK 数据应整列为空。

### 3.1 必填校验的真实口径

代码只认 `@ExcelRequired`，**共 9 个**：

```
考试大纲、题型、一级标题、一级标题内容、部分标题、题目分组、答案、分值、来源
```

🔴 **`等级*` 例外**：表头带 `*` 是为了给填表人看，`QuestionExcelEo` 的 `level` 字段上**没有 `@ExcelRequired`**。

后果：漏填 `等级` → **上传成功、不报错** → 写出 `exam_paper.level = NULL` 的卷 → 之后按等级取卷是 `a.level = #{level}` 等值比较，**这张卷永远选不到，题库里像凭空少了一卷**。

> 自查必须人工确认第 16 列整列非空。脚本无法替代这条（因为代码不校验）。

## 4. 行级写法与四个高频事故

### 4.1 分组行 vs 单题行

| 行类型 | 判据 | 写法 |
|---|---|---|
| 单题行 | `题目序号` 非空 | 一行一题，`答案`/`分值` 写该题的值 |
| 分组行 | `题目序号` **留空** | 一行展开一个区间：`答案`/`分值` 用 `,` 拆，`题目标题`/`题目内容`/`题目选项` 用 `---` 拆 |

🔴 **拆出的段数必须等于区间长度**（`题目分组` 的 `起-止`）。这是上传阶段唯一会主动报错的行级校验：

```
第 N 行：题目选项,答案,分值大小有误,无法匹配
```

### 4.2 事故一：答案里的逗号被当分隔符

`答案` 列的多答案分隔符是**半角逗号**。因为链路先把全角转半角，所以：

- 你写 `A，B`（全角）→ 变 `A,B` → 正确识别为两个答案 ✅
- 你写 `他说，好`（一个句子里含逗号）→ 变 `他说,好` → 🔴 **被拆成两个答案**，判分必然错

> 判定：**答案单元格里不允许出现任何逗号**，除非它确实是多答案分隔符。单选题答案是选项键（`A`/`B`/`C`/`D`），本来就不该有逗号。

### 4.3 事故二：选项格式

`题目选项` 只有两种合法形态（`OptionParseUtil`）：

| 形态 | 例子 | 落库 JSON |
|---|---|---|
| 键值对 | `A:苹果,B:香蕉,C:橘子` | `{"A":"苹果","B":"香蕉","C":"橘子"}` |
| 纯列表 | `A,B,C` | `{"A":"","B":"","C":""}` |

- 键必须是**连续大写字母**（`A,B,C…`），不能跳号；
- 值里可以含 `<p>`、`<img>`，会原样保留；
- 值里可以有逗号，只要后面不是「字母+:」结构就不会误切；
- 🔴 用全角冒号 `A：苹果` **能解析**（先被转半角），但不要依赖这一点 —— 链路一旦加白名单就会失效。

### 4.4 事故三：分值写成带逗号的数字

`分值` 在库里是 **varchar**，`manage` 侧按 `String` 收、`exam-service` 侧按 `BigDecimal` 解析。

- 写 `2，5`（想表达 2.5）→ 变 `2,5` → BigDecimal 解析失败 → **取卷 500**（不是上传报错，是考试开考时报错）
- 写 `2.08` 正常（半角点不受标点转换影响）

> 自查：`分值` 列只允许 `[0-9]` 和 `.`，分组行允许 `,`。

### 4.5 事故四：例题写法

| 项 | 要求 |
|---|---|
| `题目序号` | **必须写 `0`**（不是留空） |
| `分值` | **必须写单个 `0`** |
| `答案` | 写单个 `0`（例题不计分） |

🔴 `题目序号` 写 `0`（非空）会走**单题行**分支，绕过分组拆分逻辑；若是分组行却写了 `0`，整组数据错位。
🔴 例题的问题写在 `题目内容`（`passage`）里，`题目标题`（`content`）留空 —— 与正题相反，写反了界面会重复显示。

## 5. 上传前自查清单（17 条）

| # | 检查项 | 判据 | 不合格后果 |
|--:|---|---|---|
| 1 | 列头字面量 | 前 16 列表头与 §3 表逐字一致（含 `*`、括号） | EasyExcel 映射不上 → 整列空 → 必填报错或数据错列 |
| 2 | 列顺序 | 与 §3 一致 | 同上 |
| 3 | 无多余列 | 第 17 列及以后为空 | 静默丢弃，白做 |
| 4 | `考试大纲` 全表一致 | 同一文件只有一个值 | 拆成多张卷 |
| 5 | `来源` 全表一致 | 同一文件只有一个值 | 拆成多张卷 |
| 6 | `等级` 全表一致且非空 | `1`~`6` 或 `7-9` | 🔴 卷 `level=NULL`，永远取不到 |
| 7 | 9 个真必填逐行非空 | §3.1 清单 | 上传直接失败 |
| 8 | `一级标题` 是整数 | `1`/`2`/`3` | 解析异常 |
| 9 | `一级标题内容` ∈ {听力,阅读,书写} | 三选一 | 分节错乱 |
| 10 | `题目分组` 匹配 `^\d+-\d+$` | 如 `1-5` | 例题定位、分组拆分失败 |
| 11 | 分组行段数 = 区间长度 | 答案/分值按 `,`、内容按 `---` 拆 | 报「大小有误,无法匹配」 |
| 12 | 题号集合连续无重复 | 有题号的行 ∪ 分组行展开的区间 | 漏题/重题 |
| 13 | 选项键连续 | `A,B,C…` 不跳号 | 前端渲染缺项 |
| 14 | 选择题答案 ∈ 选项键 | 单选 1 个，多选多个 | 判分全错 |
| 15 | 答案单元格无多余逗号 | 例外：多答案分隔符 | 🔴 答案被拆错 |
| 16 | 分值只含数字和小数点 | 分组行允许 `,` | 🔴 取卷 500 |
| 17 | 例题：序号 `0`、分值 `0`、问题在 `题目内容` | §4.5 | 整组错位 / 界面重复 |

> 每模块分值合计 ≈100、卷合计 = 100 × 模块数，属于**入库后**验收，见《HSK题库数据-统一检查点与验收标准》§3。

## 6. 报错信息对照

| 返回 | 真实原因 | 改法 |
|---|---|---|
| `Excel 必填字段为空`（附明细列表） | 9 个真必填之一为空 | 看 `errorMessagesList` 里的「第 N 行」 |
| `第 N 行：xxx不能为空` | 单行必填缺失 | 补该行 |
| `第 N 行解析异常：...` | 类型转换失败，最常见是 `一级标题` 填了中文数字 | 改成整数 |
| `Excel 内容为空` | 读不到数据行：sheet 不是第一个 / 首行不是表头 / 全部行校验失败 | 检查 sheet 与表头 |
| `第 N 行：题目选项,答案,分值大小有误,无法匹配` | 分组行拆出的段数 ≠ 区间长度 | 补齐或删多余段 |
| `成功导入 N 题目` 但库里查不到 | 卷已存在被合并 / `level` 为空 | 查 `exam_paper` 的 `source+version+level` |
| HTTP 200 + `{"code":500}` + 日志 `NoResourceFoundException` | **不是 Excel 问题**：服务未起或路由未注册 | 重启 `manage`，不要改文件 |

## 7. 一键自查脚本

`tools/check_question_excel.py`（只读，不改文件）：

```bash
python tools/check_question_excel.py "某批题库.xlsx"
```

输出三档：

- **BLOCK**：上传必然失败或数据必错（列头不符、必填空、段数不符、分值非数字）
- **WARN**：能上传，但会被改写或静默丢弃（中文标点、第 17 列、选项全角冒号）
- **INFO**：统计信息（题号范围、模块分值合计、例题条数）
