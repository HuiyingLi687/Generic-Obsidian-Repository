# 题库导入校验流程设计

> **本文是什么**：后台导入题库时的**校验流程设计**（系统侧），目标是让脏数据**进不了库**，而不是靠填表人自觉。
>
> **为什么要有它**：现有导入只做了「9 个必填字段非空」这一层校验，剩下的全靠人工。题库由内部同事维护时还能靠肉眼兜，一旦开放给用户自己在后台导入，就没有人兜底了——错一个字母，一整套题的答案全错，而且不会报错。
>
> **定位**：本文是设计，不是操作手册。落地后替换现有的 `QuestionExcelTemplate` + `ExcelValidateUtil` 校验层。
>
> 相关：[[00HSK取卷与判分]]（脏数据最终怎么伤到考试）、[[题库Excel上传格式校验规范]]（填表侧速查，过渡期用）

---

## 0. 一句话

把导入从「**读一行、验一行、存一行**」改成「**先预演、再提交、后自检**」：预演阶段把整份文件按六道闸门过一遍，任何一行不合格就**一行都不写库**；提交阶段整批一个事务；入库后自动跑一致性断言，不达标自动回滚。

## 2. 目标与不变量

四条硬不变量，任何实现都不能破坏：

| 编号 | 不变量 | 含义 |
|---|---|---|
| **I1** | 原子性 | 一份文件 = 一个事务。要么整份进库，要么一行都不进。**禁止部分成功** |
| **I2** | 幂等性 | 同一份文件重复导入，不产生第二份卷、不产生重复题 |
| **I3** | 可追溯 | 每条被拒记录都能定位到「第几行、哪一列、原值是什么、违反哪条规则、怎么改」 |
| **I4** | 规则可演进 | 新增校验只加规则，不改主流程；规则集带版本号，能回溯某批数据是按哪版规则进来的 |

配套三条原则：

1. **校验与转换分离**：先判原值，再归一，再复核。禁止"边改边验"。
2. **规则按域生效**：同一条规则不能套所有题型（见 §3.3）。
3. **无静默修复**：任何自动修正都必须写进报告并能回退，不许悄悄改。

## 3. 流程总览

### 3.1 四段式

```
① 上传          ② 预演 Precheck        ③ 提交 Commit        ④ 自检 Verify
─────────      ─────────────────      ──────────────      ──────────────
文件落盘         G0 文件闸门            校验 token          入库后断言
算 sha256   →    G1 结构闸门       →    幂等判定       →    阈值不达标
建 taskId        G2 字段闸门            整批事务            自动回滚
                G3 语义闸门            写快照              产出报告
                G4 预检写库演练
                ↓
            报告 + token
            （有 BLOCK 则终止）
```

关键点：**预演阶段不写业务表**。要验证"能不能写进去"，用事务内试写 + 回滚（G4），或者直接做 DB 约束预检，两种都行，但都不留痕。

### 3.2 为什么不用"边读边校验"

现有实现是 `EasyExcel` 逐行回调里校验，回调结束就入库。这带来三个死角：

- **看不到全貌**：题号连续性、题组引用完整性、例题配比、卷内重复，全都需要全量数据才能判；
- **错误分散**：`onException` 只记一行，用户看到的是 20 条互不相关的报错，不知道该先修哪个；
- **无法预演**：校验和写入是同一个动作，用户点"上传"就已经在写了。

新流程把「读」和「写」彻底拆开：读取阶段只产出 `List<Row>`（内存中，含原始行号），校验阶段对 `List<Row>` 跑规则，写入阶段才碰数据库。

### 3.3 规则按域生效（最重要的一节）

一条规则是否适用，由 `examType × typeIdMapping` 决定：

```java
// 规则声明自己适用的域，引擎负责筛选
@Rule(code = "IMP-G3-02", level = BLOCK, scope = ROW)
@Domain(examType = {HSK}, types = {EXCLUDE: "reading_para_sort"})
void optionKeysMustBeContinuous(Row r, Ctx c) { ... }
```

三类域：

| 域 | 例子 | 为什么需要 |
|---|---|---|
| **考试域** | CSCA 没有等级（`level` 恒 NULL），也不填 `type_id_mapping` / `section_mapping` | 「level 必填」「映射非空」这类规则必须能声明"仅 HSK"，否则 CSCA 全量误报 |
| **题型域** | 选择题必须有选项，但 `reading_para_sort` 在题组、`reading_sort` 在 `passage`、`listening_choice_fill` 本就不给选项 | 否则 1,171 条空选项里会有 1,171 条被误报成"丢选项" |
| **卷域** | 例题（`example_question`）不参与题号连续性 | 例题题号是 `0`，天然不连续 |

没有这一层，规则写多少条都是误报源。

## 4. 六道闸门

### G0 文件闸门（不打开内容就能判）

| 码         | 规则                                                  | 级别    |
| --------- | --------------------------------------------------- | ----- |
| IMP-G0-01 | 扩展名必须是 `.xlsx`（`.xls` 拒绝，EasyExcel 对老格式的合并单元格处理不一致） | BLOCK |
| IMP-G0-02 | 文件大小 ≤ 20 MB                                        | BLOCK |
| IMP-G0-03 | 必须恰好 1 个有效 sheet；多 sheet 时默认第一个                     | BLOCK |
| IMP-G0-04 | **表头指纹**：列名 + 顺序 + 数量与模板完全一致（16 列）。多一列、少一列、改一个字都拒   | BLOCK |
| IMP-G0-05 | 无公式单元格（`=SUM(...)` 会被读成公式串而不是值）                     | BLOCK |
| IMP-G0-06 | 无合并单元格（合并行会导致 EasyExcel 只填首行，其余行必填为空却看不出原因）         | BLOCK |
| IMP-G0-07 | 数据行数 ∈ [1, 5000]                                    | BLOCK |
| IMP-G0-08 | 文件 sha256 未在 24 小时内成功导入过                            | WARN  |

`IMP-G0-04` 是最划算的一条：现有实现里第 17 列「图片名称」被静默丢弃，用户以为传上去了。表头严格比对后，这类问题**在打开第一行之前**就被拦住。图片名称仅用于导入。

### G1 结构闸门（跨行，全量判）

| 码         | 规则                                                                                               | 级别    |
| --------- | ------------------------------------------------------------------------------------------------ | ----- |
| IMP-G1-01 | 每行必然是「单题行」或「分组行」之一：`number` 非空=单题行，`number` 空=分组行。两者都空 → 空行，跳过；都非空且 `questionGroup` 是区间串 → 歧义，拒  | BLOCK |
| IMP-G1-02 | 分组行的 `questionGroup` 必须是 `start-end` 格式，且 `start ≤ end`                                          | BLOCK |
| IMP-G1-03 | 单题行的 `number` 必须是正整数                                                                             | BLOCK |
| IMP-G1-04 | 单题行的 `number` 必须落在某个分组行的区间内                                                                      | BLOCK |
| IMP-G1-05 | 同一卷内 `number` 唯一                                                                                 | BLOCK |
| IMP-G1-06 | 同一分组区间内至少 1 道单题行                                                                                 | BLOCK |
| IMP-G1-07 | 分组行之间区间不重叠                                                                                       | BLOCK |
| IMP-G1-08 | 例题（`typeId=例题`）的 `number` 允许为 `0`，不参与 04/05/06                                                   | —     |
| IMP-G1-09 | 卷的唯一键 `source+version+level`（CSCA 为 `source+version+languageVersion+subjectType`）在库中不存在，或已声明覆盖模式 | BLOCK |
| IMP-G1-10 | `section`（部分标题）与 `title1Text`（一级标题内容）的组合必须在白名单内                                                  | BLOCK |

`IMP-G1-04` 补的是个大洞：现有实现里题号 51 落在 `51-55` 组之外，是不会报错的，前端分节时这题会被静默丢弃。

### G2 字段闸门（单格）

只判单个单元格自身是否合法：不跨行、不查库、不做业务推断。

**A. 必填与枚举**

| 码 | 规则 | 级别 |
| --- | --- | --- |
| IMP-G2-01 | 9 个必填列非空 | BLOCK |
| IMP-G2-02 | `level` ∈ `{1,2,3,4,5,6,7-9}` | BLOCK |
| IMP-G2-03 | `version` ∈ `{HSK2.0, HSK3.0, CSCA}` | BLOCK |
| IMP-G2-04 | `typeId` ∈ 44 个题型白名单 | BLOCK |
| IMP-G2-05 | `title1Text` ∈ `{听力, 阅读, 书写}` | BLOCK |
| IMP-G2-06 | `title1Number` ∈ `{1,2,3}` 且与文本对应 | BLOCK |
| IMP-G2-07 | `score` 纯数字，`0 ≤ v ≤ 100` | BLOCK |

`IMP-G2-01` 必填清单：`version`、`typeId`、`title1Number`、`title1Text`、`section`、`questionGroup`、`answer`、`score`、`source`。分组行的 `score` 允许多段（`2,2,2`）。

`IMP-G2-02` **仅 HSK**。CSCA 无等级概念，此条不适用，改判 `languageVersion` + `subjectType` 非空。

`IMP-G2-04` 不匹配时给出「最相近的 3 个」建议。`IMP-G2-05` 顺手补掉一个 NPE：填「听カ」（片假名）会让整个导入 500。

**B. 文本安全与长度**

| 码 | 规则 | 级别 |
| --- | --- | --- |
| IMP-G2-08 | 无控制字符（`\n` `\t` 除外） | BLOCK |
| IMP-G2-09 | 含 `<`/`>` 时必须是合法 HTML | BLOCK |
| IMP-G2-10 | `<img>` 路径在资源白名单前缀内 | BLOCK |
| IMP-G2-11 | 单字段长度超上限 | WARN |
| IMP-G2-12 | UTF-8 合法，无 `\uFFFD` | BLOCK |

`IMP-G2-09` 白名单：标签 `p` `br` `img` `span` `u` `b` `i` `sup` `sub` `table` `tr` `td`；属性 `src` `alt` `class` `style` `width` `height`。其余（`<div>`、`onclick`）一律拒。

`IMP-G2-11` 上限：`passage` ≤ 8,000、`content` ≤ 2,000、`optionContent` ≤ 4,000 字符。

### G3 语义闸门（跨字段）

|---|---|---|

### G4 事务闸门（写入策略）

| 码 | 规则 |
|---|---|
| IMP-G4-01 | 整批一个事务，`REQUIRES_NEW`，异常全回滚 |
| IMP-G4-02 | 幂等键：`exam_type + source + version + level`（CSCA 加 `languageVersion + subjectType`）|

`IMP-G4-02/03` 解决"导两次两张卷"。注意现有 `HskExcelHandler.getPaperKey` 已经算了这个键，只是没用于查重。

### G5 质量闸门（入库后断言）

写完之后在同事务内跑一遍断言，任何一条不过 → 回滚：

| 码 | 断言 | 阈值 |
|---|---|---|
| IMP-G5-01 | 入库题数 == 预演题数 | 必须相等 |
| IMP-G5-02 | `type_id_mapping` 非空率 | 100%（HSK） |
| IMP-G5-03 | `section_mapping` 非空率 | 100%（HSK） |
| IMP-G5-04 | 答案可判率（有答案 且 客观题答案合法） | ≥ 99% |
| IMP-G5-05 | 每个 `question_group` 的题数 == 区间长度 | 100% |
| IMP-G5-06 | 每个 `section_mapping` 至少 1 题 | 100% |
| IMP-G5-07 | 空题率（三字段全空） | 0 |

### 5.3 token 机制

- `token = HMAC(sha256(file) + ruleSetVersion + mode + userId, secret)`，有效期 30 分钟；
- `commit` 时**重新计算文件 hash 并比对**——防止"预演时是好文件、提交时换成另一个"；
- 一个 token 只能用一次（Redis 标记已消费），防重复提交。

### 5.4 错误标注文件

报告除 JSON 外，支持导出一份 `.xlsx`：在原始文件基础上，把出错的单元格标红 + 插入批注（规则码 + 修复建议）。用户直接在上面改，改完重新预演。

这比"返回 20 条文本报错"有用得多，尤其对非技术的运营同事。

## 6. 校验与转换分离（关键决策）

### 6.1 现在的顺序是反的

```
当前：PunctuationConvertUtil.convertObject()  →  必填校验  →  入 validDataList
       （改数据）                                  （检查改后的）
```

改成：

```
新：读原始值  →  G2/G3 校验原值  →  归一化（记录 diff）  →  二次校验  →  入库
```

### 6.2 标点：建议**取消强制转换**

现在的 `PunctuationConvertUtil` 把 `，`→`,`、`。`→`.`、`……`→`..`、`“”`→`"`、`〈〉`→`<>`、`【】`→`[]`。对一份中文题库来说，这是**内容破坏**：

| 原文 | 转换后 | 问题 |
|---|---|---|
| `他学习特别努力。` | `他学习特别努力.` | 中文句号变英文，排版错误 |
| `……` | `..` | 变成两个点 |
| `列夫·托尔斯泰` | `列夫.托尔斯泰` | 人名间隔号变句点 |
| `〈试行〉` | `<试行>` | **生成尖括号，前端当 HTML 标签吞掉内容** |

建议：

- **入库保留原值**（中文标点原样存）；
- 需要半角的地方（如答案比对、选项分隔）在**使用侧归一**，而不是在存储侧破坏；
- 如果历史原因必须转，改成**白名单**：只把全角字母数字（`Ａ`→`A`、`１`→`1`）转半角，标点一律保留；
- 任何转换都必须产出 diff 报告（`第 12 行 passage：「，」→「,」`），可查、可回退。

### 6.3 选项解析器要重写

现在的 `OptionParseUtil` 用 `split(",")` 切分，这是 §1.1.1 那组（缺 D 项）的根因。改成状态机扫描：

```
A:公里 | , | B:故意 | , | C:温度    ← 逗号只有在「后面紧跟 X:」时才当分隔符
                                  ← 否则属于选项内容（如「A:北京,上海」）
```

规则：逗号后若匹配 `^\s*[A-Za-z]{1,2}\s*[:：]` 才是分隔符，否则是内容。同时支持 `；` `;` 作分隔符。解析失败**返回错误而不是抛异常**，交给 G3 报错。

## 7. 覆盖与幂等

### 7.1 三种模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `REJECT`（默认） | 同键卷已存在 → 直接拒，提示已有卷 ID 与题数 | 常规导入 |
| `OVERWRITE` | 旧卷软删 + 整卷快照 → 写新卷 | 修正已上线的卷 |
| `NEW_VERSION` | `version` 加后缀（`HSK2.0-r2`）| 保留旧版对照 |

### 7.2 快照表

```sql
CREATE TABLE exam_paper_snapshot (
  id BIGINT PRIMARY KEY,
  paper_id BIGINT NOT NULL,
  snapshot_json JSON NOT NULL,      -- 整卷：paper + groups + questions
  question_count INT,
  reason VARCHAR(32),               -- OVERWRITE / ROLLBACK / MANUAL
  operator_id BIGINT,
  created_time DATETIME
);
```

覆盖前快照存整卷 JSON，回滚时按 JSON 重建。**不要依赖 `deleted=1` 当备份**——软删的题仍在表里，一旦有人写 `deleted=0` 就会复活，而且软删数据会被统计口径排除，出问题时发现不了。

### 7.3 幂等的实现

```java
// 幂等键 = 业务唯一键 + 文件 hash
String bizKey = examType + "|" + source + "|" + version + "|" + level;
String idemKey = "import:idem:" + bizKey + ":" + sha256(file);

// Redis SETNX，成功才继续；失败返回上次的 taskId
Boolean first = redis.opsForValue().setIfAbsent(idemKey, taskId, Duration.ofHours(24));
```

同一份文件连点三次「上传」，只会产生一次导入。

## 8. 失败处置矩阵

| 情形 | 处置 | 用户看到 |
|---|---|---|
| G0 不过 | 立即终止，不进解析 | 「表头不匹配：第 8 列应为『部分标题内容』，实际『部分标题说明』」 |
| 任一 G1/G2/G3 有 BLOCK | **整批拒**，不写库 | 报告 + 可下载的标注 Excel |
| 只有 WARN | 允许提交，但需勾选「我已知悉 N 条警告」 | 警告清单 + 确认框 |
| G4 事务失败 | 全部回滚 | 「写入失败（第 3 步 question_group），已回滚，库中无残留」 |
| G5 断言不过 | 同事务回滚 | 「写入后自检失败：section_mapping 空值率 3%，已回滚」 |
| 提交时文件 hash 不一致 | 拒绝 | 「文件已变更，请重新预演」 |

**核心立场：宁可整批失败，不要部分成功。** 部分成功是最坏的——用户以为导进去了，实际缺了几十题，而且没人知道缺哪些。

### D.4 复核用 SQL

```sql
-- D.1 答案不在本题选项键内（扁平结构）
SELECT q.id, p.version, p.level, p.source, q.number, q.type_id_mapping,
       q.answer, q.option_content, q.deleted, p.deleted
FROM question q JOIN exam_paper p ON p.id = q.paper_id
WHERE q.answer REGEXP '^[A-Da-d]$'
  AND JSON_TYPE(q.option_content) = 'OBJECT'
  AND JSON_LENGTH(q.option_content) > 0
  AND JSON_CONTAINS_PATH(q.option_content, 'one', CONCAT('$."', UPPER(q.answer), '"')) = 0;

-- D.2 题型为 listening_choice_fill 且无选项
SELECT q.id, p.source, q.number, q.answer, q.option_content, g.option_content AS group_opt
FROM question q
JOIN exam_paper p ON p.id = q.paper_id
LEFT JOIN question_group g ON g.id = q.group_id
WHERE q.type_id_mapping = 'listening_choice_fill'
  AND JSON_LENGTH(q.option_content) = 0;

-- D.3 孤儿题
SELECT q.paper_id, COUNT(*) AS cnt
FROM question q LEFT JOIN exam_paper p ON p.id = q.paper_id
WHERE p.id IS NULL
GROUP BY q.paper_id;
```
