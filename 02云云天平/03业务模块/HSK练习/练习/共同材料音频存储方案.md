# 共同材料音频存储方案（question_shared_audio 独立表）

## 一、方案背景

### 业务现状

| 存储位置 | 用途 | 示例 |
|---|---|---|
| `question_group.audio_url` | 试卷完整听力音频（整卷连续播放，约 20-30min） | HSK3 完整听力 25min.mp3 |
| `question_shared_audio.audio_url` | 共同材料音频（一段对话/短文/新闻，被多题共享） | dialog1.mp3（对应题目21-23） |
| `question.audio_url` | 单题专属音频（每题独立音频） | q21.mp3（题目21的选项朗读） |

### 缺失场景

通过对 HSK1-HSK6 共 6 级样卷的系统分析，听力考试中存在大量"**一段材料 + 多道题**"的结构。以下是各级别需要共同材料音频的题型明细：

#### HSK1（听力 20 题，全部为单题音频，无共同材料）

| 部分 | 题型 | 题号 | 是否需要共同材料 | 说明 |
|---|---|---|---|---|
| 第一部分 | 听力：判断 | 1-5 | 否 | 每题一个独立句子 |
| 第二部分 | 听力：单选（图片选答案） | 6-10 | 否 | 每题一个独立对话/句子 |
| 第三部分 | 听力：图片匹配 | 11-15 | 否 | 5 个句子匹配 5 张图，每题独立音频 |
| 第四部分 | 听力：单选 | 16-20 | 否 | 每题一个短对话 |

**结论：HSK1 听力全部为单题音频，不需要共同材料。**

#### HSK2（听力 35 题，全部为单题音频，无共同材料）

| 部分 | 题型 | 题号 | 是否需要共同材料 | 说明 |
|---|---|---|---|---|
| 第一部分 | 听力：判断 | 1-10 | 否 | 每题一个独立句子 |
| 第二部分 | 听力：图片匹配 | 11-20 | 否 | 每题独立音频 |
| 第三部分 | 听力：单选 | 21-30 | 否 | 每题一个短对话 |
| 第四部分 | 听力：单选 | 31-35 | 否 | 每题一个短对话 |

**结论：HSK2 听力全部为单题音频，不需要共同材料。**

#### HSK3（听力 40 题，第三、四部分为长对话，需要共同材料）

| 部分 | 题型 | 题号 | 是否需要共同材料 | 说明 |
|---|---|---|---|---|
| 第一部分 | 听力：图片匹配 | 1-10 | 否 | 每题独立音频 |
| 第二部分 | 听力：判断 | 11-20 | 否 | 每题一个独立句子 |
| 第三部分 | 听力：单选（长对话） | 21-30 | **是** | 多段长对话，每段 2-3 题 |
| 第四部分 | 听力：单选（长对话/短文） | 31-40 | **是** | 多篇长对话或短文，每篇 2-3 题 |

**结论：HSK3 听力第三、四部分需要共同材料音频，约 20 题共享材料。**

#### HSK4（听力 45 题，第三部分短文理解需要共同材料）

| 部分 | 题型 | 题号 | 是否需要共同材料 | 说明 |
|---|---|---|---|---|
| 第一部分 | 听力：判断 | 1-10 | 否 | 每题一个独立句子 |
| 第二部分 | 听力：单选（对话） | 11-25 | 否 | 每题一个短对话 |
| 第三部分 | 听力：短文理解 | 26-45 | **是** | 多篇短文/长对话，每篇 2-4 题 |

**结论：HSK4 听力第三部分需要共同材料音频，约 20 题共享材料。**

#### HSK5（听力 45 题，第二部分需要共同材料）

| 部分 | 题型 | 题号 | 是否需要共同材料 | 说明 |
|---|---|---|---|---|
| 第一部分 | 听力：单选（短对话） | 1-20 | 否 | 每题一个短对话 |
| 第二部分 | 听力：单选（长对话/短文） | 21-45 | **是** | 多篇长对话/短文/采访，每篇 3-5 题 |

**结论：HSK5 听力第二部分需要共同材料音频，约 25 题共享材料。**

#### HSK6（听力 50 题，第二、三部分需要共同材料）

| 部分 | 题型 | 题号 | 是否需要共同材料 | 说明 |
|---|---|---|---|---|
| 第一部分 | 听力：单选（短对话） | 1-15 | 否 | 每题一个短对话 |
| 第二部分 | 听力：单选（长对话） | 16-30 | **是** | 多段长对话，每段 3-4 题 |
| 第三部分 | 听力：单选（短文/新闻） | 31-50 | **是** | 多篇短文/新闻/访谈，每篇 3-5 题 |

**结论：HSK6 听力第二、三部分需要共同材料音频，约 35 题共享材料。**

#### 汇总

| 级别 | 听力总题数 | 需要共同材料的题数 | 涉及部分 | 共同材料数量（预估） |
|---|---|---|---|---|
| HSK1 | 20 | 0 | 无 | 0 |
| HSK2 | 35 | 0 | 无 | 0 |
| HSK3 | 40 | ~20 | 第三、四部分 | 8-10 段 |
| HSK4 | 45 | ~20 | 第三部分 | 6-8 篇 |
| HSK5 | 45 | ~25 | 第二部分 | 7-9 篇 |
| HSK6 | 50 | ~35 | 第二、三部分 | 10-12 篇 |

这些"**共同材料**"（一段对话/短文/新闻）被多道题共享，但与 `question_group.audio_url`（试卷完整音频）不同，也不同于 `question.audio_url`（单题音频）。

### 方案目标

新增 `question_shared_audio` 独立表，专门存储**共同材料音频**，支持：
- 多题共享同一段材料
- 统一维护材料信息（URL、原文、编码）
- 支持按题号范围快速定位材料

## 二、表结构设计

### 2.1 DDL

```sql
CREATE TABLE question_shared_audio (
    id              BIGINT          NOT NULL PRIMARY KEY COMMENT '材料ID（雪花算法）',
    paper_id        BIGINT          NOT NULL COMMENT '所属试卷ID',
    group_id        BIGINT          NOT NULL COMMENT '所属大题分组ID',
    audio_url       VARCHAR(500)    NOT NULL COMMENT '共同材料音频URL（MinIO）',
    material_code   VARCHAR(32)     DEFAULT NULL COMMENT '材料编码，如 dialog1/passage2/news1',
    material_name   VARCHAR(64)     DEFAULT NULL COMMENT '材料名称，如 第一段对话/短文',
    start_number    INT             DEFAULT NULL COMMENT '起始题号（该材料覆盖的题号范围）',
    end_number      INT             DEFAULT NULL COMMENT '结束题号',
    sort_order      INT             DEFAULT 0 COMMENT '排序号',
    deleted         INT             NOT NULL DEFAULT 0 COMMENT '逻辑删除：0-未删除，1-已删除',
    created_by      BIGINT          DEFAULT NULL COMMENT '创建人',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人',
    created_time    BIGINT          DEFAULT NULL COMMENT '创建时间',
    updated_time    BIGINT          DEFAULT NULL COMMENT '更新时间',
    
    INDEX idx_group_id (group_id),
    INDEX idx_paper_id (paper_id),
    INDEX idx_material_code (material_code),
    INDEX idx_number_range (group_id, start_number, end_number)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='共同材料音频表';
```

### 2.2 字段说明

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | bigint | 否 | 主键（雪花算法） |
| `paper_id` | bigint | 否 | 所属试卷 ID，便于按试卷查询 |
| `group_id` | bigint | 否 | 所属大题分组 ID（question_group.id） |
| `audio_url` | varchar(500) | 否 | 共同材料音频 URL（MinIO） |
| `material_code` | varchar(32) | 是 | 材料编码，如 dialog1、passage2、news1 |
| `material_name` | varchar(64) | 是 | 材料名称，前端展示用 |
| `start_number` | int | 是 | 起始题号（该材料覆盖的题号范围） |
| `end_number` | int | 是 | 结束题号 |
| `sort_order` | int | 是 | 排序号 |
| `deleted` | int | 否 | 逻辑删除（BaseEntity） |
| `created_by / update_by / created_time / updated_time` | bigint | 是 | 审计字段（BaseEntity） |

## 三、与现有表的关系

### 3.1 ER 关系

```
exam_paper (1)
    │
    ▼
question_group (N)  ← question_group.audio_url = 整组完整听力
    │
    ├─► question_shared_audio (M)  ← 共同材料音频
    │       └─ material_code: dialog1/passage2
    │       └─ audio_url: 共享材料URL
    │       └─ start_number ~ end_number: 覆盖题号范围
    │
    └─► question (K)  ← question.audio_url = 单题专属音频
            └─ number: 题号
```

### 3.2 三级音频定位

```
question_group.audio_url     → 试卷完整听力（如 H10000 全部音频 30min）
        │
        ▼
question_shared_audio.audio_url → 共同材料（如 对话1 2min）
        │
        ▼
question.audio_url           → 单题音频（如 选项朗读 10秒）
```

## 五、Service 层逻辑

### 5.1 接口方法清单

| 方法 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `uploadSharedAudio` | files[], materialCode | `Result<List<UploadResult>>` | 支持单文件/批量上传到 MinIO 并写入基础记录；`paperId`、`groupId`、`startNumber`、`endNumber` 均从文件名解析并反查数据库获取；单个文件失败不影响其他文件 |

### 5.2 uploadSharedAudio 处理逻辑

```
1. 文件数组校验
   ├─ files 为空 → 抛出异常
   └─ 遍历 files 数组，对每个文件执行以下步骤

2. 单个文件处理（processSharedAudioFile）
   ├─ 基础校验
   │   ├─ 文件非空校验 → 失败：返回"文件为空，跳过"
   │   └─ 文件名非空校验 → 失败：返回"文件名为空，跳过"
   │
   ├─ 文件名解析（正则：^(.+)_(.+)_([0-9]+)-([0-9]+)\.[a-zA-Z0-9]+$）
   │   ├─ 解析试卷来源（如 HSK1_H10000）
   │   ├─ 解析材料（如 对话1）
   │   ├─ 解析起始题号（如 1）
   │   └─ 解析结束题号（如 2）
   │   失败处理：返回"文件名格式错误（{试卷来源}_{材料}_{起始题号}-{结束题号}.ext）"
   │
   ├─ 反查 paperId
   │   └─ 查询 exam_paper 表：SELECT id FROM exam_paper WHERE source = '{试卷来源}'
   │   失败处理：返回"试卷不存在"
   │
   ├─ 反查 groupId
   │   └─ 查询 question_group 表：SELECT id FROM question_group 
   │       WHERE paper_id = {paperId} AND start_number <= {起始题号} AND end_number >= {结束题号}
   │   失败处理：返回"题组不存在"
   │
   ├─ MIME 识别
   │   └─ 调用 AudioMimeUtil.getAudioMime(file)，返回标准 MIME（如 audio/mpeg）
   │   失败处理：返回"文件格式不支持"
   │
   ├─ 已存在校验（防重复上传）
   │   └─ 查询 question_shared_audio 表：
   │       WHERE paper_id = {paperId} AND group_id = {groupId}
   │         AND start_number = {起始题号} AND end_number = {结束题号}
   │   ├─ 已存在 → 跳过上传，返回 existingAudioUrl 和 questionSharedAudioId
   │   └─ 不存在 → 继续上传流程
   │
   ├─ 上传到 MinIO
   │   ├─ 拼接路径：audio/{userId}/hsk-{paperId}/{原文件名-uuid}.ext
   │   └─ 调用 MinIOUtils.uploadFile 返回 URL
   │   失败处理：返回"上传失败：{异常信息}"
   │
   ├─ 写入数据库
   │   ├─ 构建 QuestionSharedAudio 对象
   │   │   ├─ id（雪花算法，MyBatis-Plus 自动生成）
   │   │   ├─ paperId（步骤3 反查获取）
   │   │   ├─ groupId（步骤4 反查获取）
   │   │   ├─ audioUrl（步骤7 获取）
   │   │   ├─ materialCode（入参，可留空）
   │   │   ├─ materialName（步骤2 解析）
   │   │   ├─ startNumber（步骤2 解析）
   │   │   ├─ endNumber（步骤2 解析）
   │   │   └─ sortOrder（默认 0）
   │   └─ 调用 questionSharedAudioMapper.insert
   │
   └─ 返回单个文件结果
       ├─ url：音频 URL
       ├─ bound：是否成功绑定（true/false）
       ├─ questionSharedAudioId：新插入的共同材料音频记录ID
       ├─ paperId：绑定的试卷ID（绑定成功时返回）
       ├─ groupId：绑定的题组ID（绑定成功时返回）
       ├─ existingAudioUrl：已存在的音频URL（重复上传时返回）
       └─ message：提示信息

3. 汇总返回
   └─ 返回 List<UploadResult>（与输入文件一一对应）
```

**说明**：本接口负责"上传文件 + 写入基础记录"，并在写入前进行**已存在校验**（防重复上传）。

**自动解析的字段**（从文件名解析，无需前端传入）：
- `paperId`：通过试卷来源反查 `exam_paper.source` 获取
- `groupId`：通过 `paperId` + 题号范围反查 `question_group` 获取
- `materialName`：从文件名解析（如"对话1"、"短文2"）
- `startNumber`、`endNumber`：从文件名正则解析

**需前端传入的字段**：
- `materialCode`：材料编码（dialog1/passage2 等），可留空，由运营人员后续手动维护

**防重复上传机制**：
- 去重条件：`paper_id` + `group_id` + `start_number` + `end_number`
- 已存在记录时：跳过上传，返回 `existingAudioUrl` 和 `questionSharedAudioId`
- UploadResult 中 `bound=false`，message 提示已存在

## 八、文件名规则与材料编码命名

### 8.1 共同材料音频命名

```
{试卷来源}_{材料}_{起始题号}-{结束题号}.ext
```

| 组成部分 | 示例 | 来源 | 用途 |
|---|---|---|---|
| 试卷来源 | `HSK1_H10000` | 取自文件名，需与 `exam_paper.source` 一致 | 关联试卷 |
| 材料 | `对话1`、`短文2` | 文件名解析 | 填入 `material_name`（材料名称，展示用） |
| 起始题号 | `1` | 文件名解析 | 填入 `start_number` |
| 结束题号 | `2` | 文件名解析 | 填入 `end_number` |
| 扩展名 | `.mp3` / `.wav` | AudioMimeUtil 校验 | MIME 识别 |

**文件名正则**：
```java
// 匹配：试卷来源_材料_起始题号-结束题号.ext
// 示例：HSK1_H10000_对话1_1-2.mp3
String pattern = "^(.+)_(.+)_([0-9]+)-([0-9]+)\\.[a-zA-Z0-9]+$";
//                  ↑      ↑       ↑       ↑
//              试卷来源  材料   起始题号  结束题号
```

### 8.2 材料编码（materialCode）命名规则

#### 编码格式

```
{材料类型}{序号}
```

#### 材料类型对照表

| 材料类型 | 编码前缀 | 适用级别 | 说明 | 示例 |
|---|---|---|---|---|
| 短对话 | `dialog` | HSK3-HSK6 | 两人简短对话，2-3 题共用 | dialog1, dialog2 |
| 长对话 | `long_dialog` | HSK4-HSK6 | 较长对话，3-4 题共用 | long_dialog1 |
| 短文 | `passage` | HSK3-HSK6 | 叙述性短文/故事，3-5 题共用 | passage1, passage2 |
| 新闻 | `news` | HSK4-HSK6 | 新闻报道，3-4 题共用 | news1, news2 |
| 采访 | `interview` | HSK5-HSK6 | 访谈类材料，4-5 题共用 | interview1 |
| 演讲 | `speech` | HSK6 | 演讲/发言材料，4-5 题共用 | speech1 |
| 报告 | `report` | HSK6 | 报告/讲座材料，4-5 题共用 | report1 |

#### 各级别材料编码示例

**HSK3**：
- dialog1（对话1）
- dialog2（对话2）
- passage1（短文1）
- passage2（短文2）

**HSK4**：
- passage1（短文1）
- passage2（短文2）
- news1（新闻1）
- news2（新闻2）
- long_dialog1（长对话1）

#### 编码生成规则

1. **同一题组内，按材料出现顺序编号**，从 1 开始
2. **材料类型由运营人员根据实际材料内容手动填写**（初期可留空）
3. **编码在同一试卷内唯一**，不同试卷间可重复

### 8.3 音频文件名与字段映射关系

**核心规则**：文件名解析后填入 `material_name`、`start_number`、`end_number`，`materialCode` 根据材料类型手动填写（可留空）。

| 文件名 | 解析结果 | 写入字段 |

**materialCode 填写示例**（根据材料类型，可留空）：

| 文件名 | material_name（自动解析） | materialCode（手动填写） | start_number | end_number |
|---|---|---|---|---|
| `HSK3_H31001_对话1_21-23.mp3` | 对话1 | dialog1（可留空） | 21 | 23 |
| `HSK3_H31001_短文2_24-26.mp3` | 短文2 | passage2（可留空） | 24 | 26 |
| `HSK6_H61000_材料_47-50.wav` | 材料 | report1（可留空） | 47 | 50 |

**字段职责说明**：
- `material_name`：从文件名解析，用于前端展示（如"对话1"、"短文2"）

## 十一、注意事项

1. **试卷必须先导入**：共同材料上传前，必须先通过 Excel 导入试卷和题目，否则 `group_id` 和题号范围无法确定
2. **materialCode 唯一性**：同一题组（group_id）下，materialCode 建议唯一，如 dialog1、dialog2
3. **题号范围必须连续**：start_number 和 end_number 定义该材料覆盖的连续题号范围
4. **防重复上传**：上传前根据 `paper_id + group_id + start_number + end_number` 去重查询，已存在则跳过上传
5. **删除联动**：删除题组（question_group）时，应同步删除关联的共同材料（逻辑删除）
6. **索引利用**：查询共同材料时优先使用 `idx_number_range` 索引（group_id + start_number + end_number）

## 十三、完整数据流总结

```
1. 运营人员准备音频文件：HSK6_H61000_材料_47-50.wav
2. 调用 POST /file/uploadSharedAudio
   参数：files, materialCode=dialog1（可留空）
   系统从文件名解析：source=HSK6_H61000, materialName=材料, startNumber=47, endNumber=50
3. 系统校验：
   a. 查询 exam_paper WHERE source = 'HSK6_H61000' → paperId
   b. 查询 question_group WHERE paper_id = paperId AND start_number <= 47 AND end_number >= 50 → groupId
   c. 去重查询 question_shared_audio WHERE paper_id AND group_id AND start_number AND end_number
      ├─ 已存在 → 跳过，返回 existingAudioUrl
      └─ 不存在 → 继续上传
4. 系统上传到 MinIO → audio/3232344/hsk-{paperId}/HSK6_H61000_材料_47-50-uuid.wav
5. 写入 question_shared_audio 表（含 material_name 字段）
6. 练习时（practice-service）：
   a. 根据 group_id + number 查询共同材料
   b. 返回 audio_url 给前端
   c. 前端播放共同材料音频
```
