# 真题练习 - 听力模块接口设计

> 基于《汉考宝_iOS_真题练习_听力模块_PRD.md》、《hsk_ios_listening_prototype_v7.html》原型与现有 `practice-service` 阅读模块架构分析得出。复用 `practice` 核心实体表（`PracticeRecord`/`PracticeAnswer`/`PracticeReport` 等），听力专属逻辑围绕"音频素材下发-版本绑定-客观题作答-报告快照"展开。
>
> - 模块包路径：`com.hsktreasure.practice.listening`
> - 网关前缀：`/api/practice/listening`（网关剥离 `/api`，Controller 内部路径为 `/practice/listening`）
> - 三层架构：Controller（参数接收+鉴权） → Service（业务编排） → Mapper（数据访问，复用 `practice.core.mapper`）
> - 鉴权约定：所有写操作与个性化查询需 `Authorization: Bearer <APP_JWT>` + `X-Client-Type: APP`，通过 `BaseController.requireAuthenticatedAppUserId(request, clientType)` 解析 `userId`，作为 Service 首参，禁止信任客户端传入的 userId。
> - 统一响应：`Result<T>` 包络 `{code, message, data}`；业务错误 HTTP 200 + 非 200 code（`BusinessException(ErrorCode)`）。

**复用核心实体（不新增表）：** `PracticePaper`、`PracticePaperStructure`（板块）、`QuestionGroup`、`Question`、`QuestionSharedAudio`（材料音频）、`PracticeRecord`、`PracticeAnswer`、`PracticeReport`、`PracticePartSetting`、`PracticeModuleLevelConfig`、`PracticeLevelConfig`。

## 四、接口详细设计

> 每个接口先描述业务逻辑（做什么），再给出三层代码逻辑（Controller / Service / Mapper）。

### 1. 等级与目录

#### 1.1 查询等级列表
`GET /practice/listening/levels`

**做什么**：用户进入听力模块时调用，返回**单个等级**的试卷列表和答题汇总。前端将上次选择的等级存在本地（localStorage），请求时带上；第一次进入不带，默认返回 HSK1。退出后再进入，自动停在上次的等级界面。

**入参**：
- `levelCode`（查询参数，可选）：前端从本地存储带上上次选择的等级。不带则默认 `HSK1`。
- `Authorization`（可选）：已登录用户返回答题进度；未登录不返回进度数据。

**返回**：
```json
{
  "levelCode": "HSK2",
  "paperCount": 2,
  "papers": [
    {
      "paperId": 201,
      "paperCode": "HSK2_H20000",
      "status": "completed",
      "completedCount": 35,
      "totalCount": 35
    },
    {
      "paperId": 202,
      "paperCode": "HSK2_H20001",
      "status": "not_started",
      "completedCount": 0,
      "totalCount": 35
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `levelCode` | 当前返回的等级编码（前端传入的上次选择等级，未传则=HSK1） |
| `paperCount` | 该等级下试卷总数 |
| `papers[].paperId` | 试卷ID |
| `papers[].paperCode` | 试卷编码（如 "HSK2_H20000"） |
| `papers[].status` | `not_started` / `in_progress` / `completed`（未登录均为 `not_started`） |
| `papers[].completedCount` | 该试卷**已提交**记录的已答题数（未登录=0；草稿已答不计入） |
| `papers[].totalCount` | 该试卷总题数 |

**业务逻辑**：
1. 确定返回哪个等级：取 `levelCode` 参数，未传则默认 HSK1；
2. 查该等级下所有已发布的试卷；
3. 若用户已登录，批量查询每套试卷的答题统计，按 `(paperId, structureId, status)` **取最新一条 `practice_record.id`**，JOIN `practice_answer` 精确统计 `answered=1` 的题数，区分草稿（status=1）与已提交（status=3）：
   - `completedCount` = `submittedAnsweredCount`（仅已提交记录的已答题数）
   - `status` 判定：`submittedAnsweredCount > 0` → `completed`；否则 `draftAnsweredCount > 0` → `in_progress`；都为 0 → `not_started`
   - 草稿答完所有题但未提交 → `in_progress`（**只有提交才算 completed**）
4. 未登录则 `status` 全为 `not_started`、`completedCount` 全为 0；
5. 汇总试卷总数 `paperCount`。

**涉及表**：查询 `exam_paper`、`practice_record`、`practice_answer`（后两者已登录才查）

**三层逻辑**：
- **Controller**：`@RequestParam(required=false) levelCode`（默认 HSK1）；尝试解析 `userId`（未登录为 `null`）；调 `listeningCatalogService.getLevelOverview(levelCode, userId)` 返回 `Result<ListeningLevelOverviewResponse>`。
- **Service**：
  1. `levelCode` 为空则默认 `"HSK1"`。
  2. 查 `ExamPaper`（`level=levelCode`），获取该等级下所有试卷。
  3. 若 `userId != null`，调 `recordMapper.selectAnsweredCountByPaper(userId, paperIds)` 批量查询，返回每套试卷的 `draftAnsweredCount` 与 `submittedAnsweredCount`。若 `userId == null`，跳过此步，两者均为 0。
  4. `completedCount` 取 `submittedAnsweredCount`；`status` 按 `submittedAnsweredCount > 0` → `completed`，否则 `draftAnsweredCount > 0` → `in_progress`，否则 `not_started` 判定。
- **Mapper**：`ExamPaperMapper.selectList(...)` + `PracticeRecordMapper.selectAnsweredCountByPaper(userId, paperIds)`（批量自定义 XML，仅已登录时调用）。

**`selectAnsweredCountByPaper` SQL 关键逻辑**：
```sql
-- 内层：按 (paperId, structureId, status) 取最新一条 record.id
SELECT MAX(id) AS max_id FROM practice_record
WHERE user_id=? AND deleted=0 AND status IN (1,3) AND paper_id IN (...)
GROUP BY paper_id, structure_id, status

-- 中层：JOIN practice_answer 精确统计 answered=1 的题数
LEFT JOIN (
  SELECT practice_record_id, COUNT(*) AS answered_cnt
  FROM practice_answer WHERE answered=1 AND deleted=0
  GROUP BY practice_record_id
) pa ON pa.practice_record_id = pr.id

-- 外层：按 paperId 汇总，用 CASE WHEN 区分草稿/已提交
SUM(CASE WHEN pr.status=1 THEN answered_cnt ELSE 0 END) AS draftAnsweredCount,
SUM(CASE WHEN pr.status=3 THEN answered_cnt ELSE 0 END) AS submittedAnsweredCount
```

> **设计要点**：
> - **取最新记录而非答题最多**：用 `MAX(id)` 定位每个 `(paper, structure, status)` 维度下最新一条记录，避免历史草稿（答题多）覆盖新草稿（答题少）。
> - **精确计数而非冗余字段**：不依赖 `practice_record.answered_count` 冗余字段，直接 JOIN `practice_answer` 统计 `answered=1` 行数，避免字段未同步导致脏数据。
> - **草稿/已提交分离**：`GROUP BY status` 让草稿和已提交各自取最新，互不覆盖；`completedCount` 只算已提交，草稿答完仍是 `in_progress`。

#### 1.3 查询板块列表
`GET /practice/listening/papers/{paperId}/parts`

**做什么**：返回某张试卷的听力题型板块列表，每个板块附带状态。原型中板块卡片展示：题型名称、总题数、已做/正确/错误统计。

**入参**：`paperId`（路径参数）

**返回**：
```json
{
  "paperId": 201,
  "paperCode": "HSK2_H20000",
  "parts": [
    {
      "structureId": 1001,
      "partName": "第一部分",
      "typeName": "看图判断题",
      "questionCount": 5,
      "status": "completed",
      "doneCount": 5,
      "correctCount": 4,
      "wrongCount": 1,
      "sortOrder": 1
    },
    {
      "structureId": 1002,
      "partName": "第二部分",
      "typeName": "图片匹配题",
      "questionCount": 5,
      "status": "in_progress",
      "doneCount": 3,
      "correctCount": 0,
      "wrongCount": 0,
      "sortOrder": 2
    },
    {
      "structureId": 1003,
      "partName": "第三部分",
      "typeName": "细节选择题",
      "questionCount": 5,
      "status": "not_started",
      "doneCount": 0,
      "correctCount": 0,
      "wrongCount": 0,
      "sortOrder": 3
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `parts[].structureId` | 板块 ID（来自 `practice_paper_structure.id`） |
| `parts[].partName` | 板块名称（如"第一部分"，来自 `parts_config`） |
| `parts[].typeName` | 题型名称（如"看图判断题"，来自 `parts_config`） |
| `parts[].questionCount` | 该板块题数（**来自 `question_group` 表，按 `sort_order` 分组取 `SUM(end_number - start_number + 1)`**；查不到时为 0） |
| `parts[].sortOrder` | 排序序号（来自 `parts_config`） |
| `parts[].status` | 板块状态：`not_started` / `in_progress` / `completed` |
| `parts[].doneCount` | 已答题数 |
| `parts[].correctCount` | 正确数（仅已提交板块有值） |
| `parts[].wrongCount` | 错误数（仅已提交板块有值）；**未作答的题计入错误**，即 `wrongCount = totalCount - correctCount` |

**业务逻辑**：
1. 查试卷获取等级 → 查 `practice_module_level_config` 获取 `parts_config` JSON，解析后得到板块元数据（`partName`、`typeName`、`questionCount`、`sortOrder`），按 `sortOrder` 排序；
2. 查 `practice_paper_structure`（`paperId=? AND contentType='SEC_LISTEN'`）获取 `structureId`，按 `sortOrder` 排序；
3. 查 `question_group`（`paper_id=? AND section='听力'`），按 `sort_order` 分组，每组题数 = `SUM(end_number - start_number + 1)`；
4. 将 `parts_config` 元数据、`practice_paper_structure` 的 `structureId`、`question_group` 的题数按 `sortOrder` 一一匹配；`questionCount` 取 `question_group` 的统计值，查不到时为 0；
5. 对每个板块判定状态：
   - 有进行中草稿 → `in_progress`，附带已答/总题数
   - 有已提交且报告就绪 → `completed`，附带正确/错误统计
   - 无记录 → `not_started`
6. 内容已下架 → 不展示。

**涉及表**：查询 `practice_module_level_config`、`practice_paper_structure`、`question_group`、`practice_record`、`practice_report`

**三层逻辑**：
- **Controller**：`requireAuthenticatedAppUserId`；调 `service.listParts(userId, paperId)` 返回 `ListeningPartsResponse`。
- **Service**：
  1. 查 `PracticePaper` 获取 `level`，查 `PracticeModuleLevelConfig`（`sectionMapping='SEC_LISTEN' AND level=? AND enabled=1`），解析 `partsConfig` JSON 得到板块元数据列表，按 `sortOrder` 排序；
  2. 查 `PracticePaperStructure`（`paperId=? AND contentType='SEC_LISTEN'`）获取 `structureId`，按 `sortOrder` 排序；
  3. 一次性查 `PracticeQuestionGroup`（`paper_id=? AND section='听力' AND deleted=0`），按 `sort_order` 分组累加 `end_number - start_number + 1`，形成 `Map<sortOrder, 题数>`；
  4. 三者按 `sortOrder` 匹配，`questionCount` 取 `question_group` 的统计值，查不到时为 0；
  5. 对每个板块，查 `PracticeRecord`：有已提交且报告就绪（`selectLatestReady`）→ `completed`，取其 `answeredCount`/`correctCount`/`wrongCount`；有进行中草稿（`selectInProgress`）→ `in_progress`，取其 `answeredCount`；否则 → `not_started`。
- **Mapper**：`PracticeModuleLevelConfigMapper.selectOne(...)` + `PracticePaperStructureMapper.selectListeningParts(paperId)` + `PracticeQuestionGroupMapper.selectList(...)` + `PracticeRecordMapper.selectInProgress(userId, paperId, structureId)` / `selectLatestReady(userId, structureId)`。

### 2. 开始与恢复作答

#### 2.1 开始/恢复/重开作答
`POST /practice/listening/records/start`

**做什么**：用户在板块列表页点击【练习】时调用。如果该板块之前有未完成的草稿，就恢复上次答题记录；没有就新建一条记录。拿到记录后前端调 2.3 获取题目清单开始答题。

**入参**：`structureId`（板块 ID）、`restart`（是否强制重开，默认 false）

**返回**：
```json
{
  "recordId": 10001,
  "status": "in_progress",
  "currentQuestionId": 501,
  "durationSeconds": 180,
  "totalCount": 5,
  "answers": [
    { "questionId": 501, "answered": true, "answer": "true" },
    { "questionId": 502, "answered": false, "answer": null }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `recordId` | 作答记录 ID |
| `status` | `in_progress`（恢复草稿）/ `created`（新建记录） |
| `currentQuestionId` | 当前停留的题号 |
| `durationSeconds` | 累计有效时长（秒） |
| `totalCount` | 该板块总题数 |
| `answers[]` | 已保存的答案列表（新建记录时为空数组） |

**业务逻辑**：
1. 校验 `structureId` 存在且 `sectionMapping='SEC_LISTEN'`，状态可用；
2. 查该用户+该板块是否有 `status IN (0,1)` 的草稿：
   - **有草稿 + restart=false** → 恢复该草稿，返回当前进度（题号、答案、时长），不清空任何数据；
   - **无草稿 或 restart=true** → 新建 `PracticeRecord`（`status=1`），初始化所有题目的空 `PracticeAnswer` 行（`answered=0`）；
3. 草稿对应的内容版本已下架 → 返回内容已下架说明；
4. 草稿被封禁 → 报错提示，不自动创建新记录。

**防并发**：对同一用户+同一板块加行锁，防止重复创建。

**涉及表**：查询 `practice_paper_structure`、`question`；写入 `practice_record`、`practice_answer`

**三层逻辑**：
- **Controller**：`@RequestBody @Valid ListeningRecordStartRequest{structureId, restart}`；`requireAuthenticatedAppUserId`；调 `service.start(userId, request)` 返回 `ListeningRecordResponse`。
- **Service**：
  1. 校验 `structureId` 存在且可用。
  2. `SELECT ... FOR UPDATE` 查 `PracticeRecord` 中 `(userId, structureId)` 的草稿。
  3. 有草稿且 `restart=false`：返回草稿 + 关联的 `PracticeAnswer` 列表。
  4. 无草稿或 `restart=true`：新建 `PracticeRecord`，批量插入空 `PracticeAnswer`，返回新建记录。
  5. 版本已下架：沿用历史快照；被封禁：抛 `BusinessException(ErrorCode.RESOURCE_FORBIDDEN)`。
- **Mapper**：`PracticeRecordMapper.selectInProgressForUpdate(userId, structureId)` + `insert` / `selectById` + `PracticeAnswerMapper.selectByRecord(recordId)` / `insertBatch`。

  2. 通过 `PracticeRecord.structureId` → `PracticePaperStructure` 校验板块可用性；
  3. 按 `sortOrder` 加载该板块下所有 `Question`；筛选 `layout` 为 `textChoice_shareAudio` 或 `passageGroup` 的题目，按 `groupId` 批量加载 `QuestionSharedAudio`（按 `paperId+groupId` 匹配），构建 `groupId → List<QuestionSharedAudio>` 映射；
  4. 关联 `PracticeAnswer` 回填用户当前答案及 `answered` 状态；
  5. 逐题组装响应：
     - **`layout`**：直接读取 `question.layout` 字段；
     - **共同材料匹配**：若 `layout` 为 `textChoice_shareAudio` 或 `passageGroup` 且 `groupId` 非空，按 `start_number<=number<=end_number` 在映射中查找命中的 `QuestionSharedAudio`，命中则同时取 `audio_url`（作为 `share_audio_url`）和 `material_code`（作为 `variant`）；未命中则两者均为 `null`；
     - 直接透传 `question` 表字段：`passage`、`audio_url`、`option_content`、`number`。
- **Mapper**：`PracticeRecordMapper.selectById(recordId)` + `PracticePaperStructureMapper.selectById(structureId)` + `QuestionMapper.selectByStructure(structureId)` + `QuestionSharedAudioMapper.selectByPaperAndGroup(paperId, groupIds)` + `PracticeAnswerMapper.selectByRecordId(recordId)`。

#### 2.4 暂停保存
`POST /practice/listening/records/{recordId}/pause`

**做什么**：用户切后台、锁屏、退出答题页时调用，保存当前进度。原型在 `visibilitychange`/`pagehide`/`beforeunload` 时自动触发保存。

**入参**：`currentQuestionId`、`durationSeconds`（累计有效时长）、草稿答案列表、`clientSequence`、`baseVersion`

**返回**：更新后的记录

**业务逻辑**：
1. 校验乐观锁版本（`baseVersion`），版本冲突 → 返回错误，由用户选择保留哪个版本；
2. 更新当前题号、累加有效时长、更新最后保存时间、版本+1；
3. 批量写入答案草稿（不固化快照）。

**涉及表**：写入 `practice_record`、`practice_answer`

**三层逻辑**：
- **Controller**：`@RequestBody ListeningRecordPauseRequest{currentQuestionId, durationSeconds, List<ListeningAnswerSaveRequest> draftAnswers, clientSequence, baseVersion}`；调 `service.pause(...)` 返回 `ListeningRecordResponse`。
- **Service**：
  1. `SELECT FOR UPDATE` 锁 `PracticeRecord`，校验 `status=1`。
  2. 乐观锁校验 `baseVersion`：`record.version == request.baseVersion`，否则抛 `BusinessException(ErrorCode.RECORD_VERSION_CONFLICT)`。
  3. 更新 `currentQuestionId`、`durationSeconds`（累加）、`lastSavedTime`、`version+1`。
  4. 批量 upsert `PracticeAnswer`（仅草稿，不固化快照）。
- **Mapper**：`PracticeRecordMapper.updateById`（带 `@Version`）+ `PracticeAnswerMapper.batchUpsert`（XML）。



### 3. 答案保存

#### 3.1 单题答案保存
`PUT /practice/listening/records/{recordId}/answers/{questionId}`

**做什么**：用户选择答案后，500-1000ms 防抖同步到服务端。

**入参**：`selectedOptionId`（稳定选项标识，如 `A`/`B`等字母）、`clientSequence`、`baseVersion`

**返回**：保存后的答案

**业务逻辑**：
1. 校验记录归属和状态（必须为"作答中"）；
2. 乐观锁检测：版本冲突 → 返回冲突摘要（含云端最新答案），由客户端让用户选择保留本机还是云端；
3. 无冲突 → 写入答案，标记为"已答"，更新保存时间；
4. 判断题用 `true`/`false` 稳定标识，不依赖"正确/错误"中文文案。

**涉及表**：查询 `practice_record`；写入 `practice_answer`、`practice_record`

**三层逻辑**：
- **Controller**：`@RequestBody @Valid ListeningAnswerSaveRequest{selectedOptionId, clientSequence, baseVersion}`；调 `service.saveOne(...)` 返回 `ListeningAnswerResponse`。
- **Service**：
  1. 校验记录归属与状态（`status=1`）。
  2. `SELECT FOR UPDATE` 锁 `PracticeRecord`，乐观锁校验 `baseVersion`；冲突时返回冲突摘要。
  3. 无冲突则写入/更新 `PracticeAnswer`（`answer = selectedOptionId`、`answered = 1`、`lastModifiedTime` 更新）。
  4. `PracticeRecord.lastSavedTime = now`，`version+1`。
- **Mapper**：`PracticeAnswerMapper.selectForUpdate(recordId, questionId)` + `updateById` + `PracticeRecordMapper.updateById`。

### 4. 提交与报告

#### 4.1 提交
`POST /practice/listening/records/{recordId}/submit`

**做什么**：用户确认提交整个板块的答案，触发评分并生成报告。原型中提交确认弹窗展示"已完成 X/Y"，未完成时提示"还有 N 题未完成，仍要提交吗？"。

**入参**：`durationSeconds`、`idempotencyKey`（幂等键）、最后一批答案、`baseVersion`、`clientSequence`

**`idempotencyKey` 生成规则**（客户端生成，后端仅做非空校验与等值比对）：
- 格式：`submit-{recordId}-{yyyyMMddHHmmss}`，示例：`submit-1234567890-20260729220000`
- 每次用户"点提交"生成一个新 key；同一提交动作的重试（网络失败/断网恢复）必须复用同一 key
- 用户重新发起提交（如改了答案后再提交）时生成新 key
- 目的：保证同一 `recordId + idempotencyKey` 重复提交始终返回同一 `reportId`，不生成第二份 Report

**返回**：报告摘要（状态可能为"评分中"或"已就绪"）

**业务逻辑**（原子事务）：
1. **幂等检查**：相同 `idempotencyKey` 重复提交 → 直接返回已生成的报告 ID，不重复处理；
2. 校验记录归属、状态为"作答中"、版本一致；
3. 接收并固化最后一批答案；
4. **固化快照**：把当前时刻的题目内容（含 layout、passage、题目音频、材料音频、选项文本/拼音/图片等 option_content 原始JSON）、标准答案、解析全部存入快照字段，之后不可修改；
5. 将记录状态改为"已提交"，记录提交时间、有效时长、幂等键；
6. 创建报告骨架（状态="评分中"）；
7. 触发客观题评分（比对用户选项 ID 与正确选项 ID）；
8. 任一步骤失败不留下"已提交但无报告"的孤立状态。

**涉及表**：查询 `practice_record`、`practice_answer`、`question`；写入 `practice_record`、`practice_answer`、`practice_report`

**三层逻辑**：
- **Controller**：`@RequestBody @Valid ListeningSubmitRequest{durationSeconds, idempotencyKey, List<ListeningAnswerSaveRequest> finalAnswers, baseVersion, clientSequence}`；调 `listeningReportService.submit(userId, recordId, request)` 返回 `ListeningReportResponse`。
- **Service**（`ListeningSubmissionFinalizer` 内部组件，原子事务）：
  1. `SELECT FOR UPDATE` 锁 `PracticeRecord` + 全部 `PracticeAnswer`。
  2. 幂等检查：`record.idempotencyKey == request.idempotencyKey` → 直接返回已生成报告。
  3. 校验：`status=1`、`baseVersion` 一致、归属。
  4. 接收最后一批答案，固化写入 `PracticeAnswer`。
  5. 固化快照：`questionSnapshot`（含 layout、passage、audio_url、share_audio_url、option_content 原始JSON等提交时点内容）/`groupSnapshot`/`optionSnapshot`/`standardAnswerSnapshot`/`analysisSnapshot` 写入提交时点版本。
  6. `PracticeRecord.status=3, submittedTime=now, durationSeconds, idempotencyKey, version+1`。
  7. 生成 `PracticeReport` 骨架（`reportStatus=1 GENERATING`）。
  8. 触发客观题评分（同步或异步）。
- **Mapper**：`PracticeRecordMapper.updateById` + `PracticeAnswerMapper.batchUpdateSnapshot`（XML）+ `PracticeReportMapper.insert`。

#### 4.2 获取学习报告
`GET /practice/listening/records/{recordId}/report`

**做什么**：提交后查看报告。原型中报告页展示：正确率百分比（大号数字）、答对 X/总 Y、答题时长、题号矩阵（正确=绿色，错误=红色，点击可进入单题回顾）。

**入参**：`recordId`

**返回**：
- `reportId`、`reportStatus`：`PROCESSING` / `READY` / `FAILED_RETRYABLE` / `FAILED_FINAL`
- `accuracyRate`：正确率百分比
- `totalQuestions`、`correctCount`、`wrongCount`（= 总数 - 正确数）、`answeredCount`
- `durationSeconds`、`submittedTime`
- `rows[]`：题号矩阵，每项 `{ number, questionId, questionType, layout, answered, isCorrect, userAnswer, correctAnswer }`

**关键规则**：
- 报告只有**正确/错误**两种结果，未作答统一计入错误，不展示"未作答"统计
- 报告未就绪时返回当前状态，前端展示加载中

**涉及表**：查询 `practice_report`、`practice_answer`

**三层逻辑**：
- **Controller**：调 `service.getReport(userId, recordId)` 返回 `ListeningReportResponse`。
- **Service**：校验归属；加载 `PracticeReport` + `PracticeAnswer`；组装报告摘要和题号矩阵。
- **Mapper**：`PracticeReportMapper.selectByRecord(recordId)` + `PracticeAnswerMapper.selectByRecord(recordId)`。

#### 4.3 重试评分
`POST /practice/listening/records/{recordId}/report/retry`

**做什么**：报告评分失败时，重新触发评分。

**入参**：`recordId`

**返回**：最新报告状态

**业务逻辑**：仅对 `FAILED_RETRYABLE` 状态的报告生效，重新触发评分；不回滚 Attempt，已固化的快照不变。

**涉及表**：查询 `practice_report`、`practice_answer`；写入 `practice_report`、`practice_answer`

**三层逻辑**：
- **Controller**：调 `service.retryReport(userId, recordId)`。
- **Service**：校验 `reportStatus=FAILED_RETRYABLE`；`UPDATE PracticeReport SET reportStatus=1`；重新触发评分。
- **Mapper**：`PracticeReportMapper.updateReportStatus(recordId, 1)`。

`GET /practice/listening/parts/{structureId}/reports/latest`

**做什么**：在题型板块选择页，快捷展示最近一次练习的报告摘要。

- **Mapper**：`PracticeRecordMapper.selectLatestSubmitted(userId, structureId)` + `PracticeReportMapper.selectByRecord`。

#### 4.5 单题回顾
`GET /practice/listening/records/{recordId}/report/questions/{questionId}`

**做什么**：在学习报告中点击某道题，查看详细的作答回顾。原型中回顾弹窗从底部弹出，展示：题型+题号、题干、音频播放器（材料音频→题目音频）、图片/文字陈述、选项列表（标注用户所选+正确答案）、解析文本。未作答题目额外提示"本题未作答，正确答案已在选项中标出"。

**入参**：`recordId`、`questionId`

**返回**（结构与 2.3 一致，数据来源为提交时点快照，额外增加 `analysis` / `isCorrect` / `standardAnswer`）：

各 layout 返回示例（与 2.3 对应示例字段完全一致，新增回顾字段）：

- `imageJudge`（看图判断题）：
```json
{
  "questionId": 501, "no": 1, "layout": "imageJudge",
  "passage": "",
  "variant": null,
  "answered": true,
  "userAnswer": "A",
  "isCorrect": true,
  "standardAnswer": "A",
  "audio_url": "",
  "option_content": {},
  "share_audio_url": null,
  "analysis": "解析文本"
}
```

- `textChoice_shareAudio` / `passageGroup`（命中共同材料音频）：
```json
{
  "questionId": 541, "no": 41, "layout": "passageGroup",
  "passage": null,
  "variant": "passage1",
  "answered": false,
  "userAnswer": null,
  "isCorrect": false,
  "standardAnswer": "C",
  "audio_url": "",
  "option_content": {},
  "share_audio_url": "http://www.example.com/hsk/audio/.../material.wav",
  "analysis": "解析文本"
}
```

> 其他 layout（`imageChoice`/`imageMatch`/`textJudge`/`textChoice`）结构与 2.3 对应示例一致，`variant` / `share_audio_url` 为 `null`，末尾追加 `isCorrect` / `standardAnswer` / `analysis` 三个回顾字段。

**字段说明**：
| 字段 | 来源 | 说明 |
|---|---|---|
| `layout` | `questionSnapshot.layout` | 直接读取快照，枚举与 2.3 一致 |
| `passage` / `audio_url` / `option_content` / `number` / `variant` / `share_audio_url` | `questionSnapshot` | 与 2.3 字段含义、来源一致，仅改为从快照读取 |
| `answered` / `userAnswer` | `PracticeAnswer` | 与 2.3 一致 |
| `isCorrect` | 评分结果 | 2.3 无此字段（作答中不判分），4.5 新增 |
| `standardAnswer` | `standardAnswerSnapshot` | 2.3 绝不返回，4.5 新增（回顾需展示正确答案） |
| `analysis` | `analysisSnapshot` | 2.3 绝不返回，4.5 新增（回顾需展示解析） |

**关键规则**：
- 所有内容严格来自提交时点的快照（`questionSnapshot`/`standardAnswerSnapshot`/`analysisSnapshot`），不拉取 CMS 最新数据
- 回顾音频固定 1x 播放，不隐式继承答题页的 0.5x
- 不下发音频文字稿（`audioText`）、字幕、译文
- 单题回顾不支持直接切题，关闭后回到报告页
- **共同材料音频判定规则**：按快照中 `layout` 判定（与 2.3 一致）：
  - `textChoice_shareAudio` 或 `passageGroup` → 展示 `share_audio_url`（材料音频）
  - 其他 layout → `share_audio_url` 为 `null`
- **`variant` 字段**：仅命中共同材料的 `textChoice_shareAudio` / `passageGroup` 题目返回，值 = 快照中 `question_shared_audio.material_code`；其他情况为 `null`（与 2.3 一致）
- `pinyin` 字段仅 HSK1-2 返回，HSK3 及以上不返回（与 2.3 一致）
- `passageGroup` 题目回顾时，材料音频独立展示在题目音频之前

**涉及表**：查询 `practice_answer`、`practice_report`

**三层逻辑**：
- **Controller**：调 `service.getQuestionReport(userId, recordId, questionId)` 返回 `ListeningQuestionReportResponse`。
- **Service**：
  1. 校验 `recordId` 归属 `userId` 且 `reportStatus=2`（报告就绪）；
  2. 从 `PracticeAnswer.questionSnapshot` 反序列化，直接读取快照中的 `layout`、`passage`、`audio_url`、`share_audio_url`、`variant`、`option_content`、`number` 等字段（结构与 2.3 返回一致）；
  3. 按快照中 `layout` 判定是否展示共同材料音频（与 2.3 判定规则一致）；
  4. 关联 `standardAnswerSnapshot`、`analysisSnapshot` 补充正确答案和解析；
  5. 关联 `userAnswer` 和评分结果标注用户所选及 `isCorrect`，若 `userAnswer` 为空则标记未作答。
- **Mapper**：`PracticeAnswerMapper.selectByRecordQuestion(recordId, questionId)` + `PracticeReportMapper.selectByRecord`。

## 五、评分逻辑

> 听力模块为确定性客观题评分（判断/单选/图片单选/图片匹配），无需 AI 介入。

**评分流程**：
1. 逐题比对用户选项标识与正确选项标识，完全一致 → 正确，否则 → 错误；
2. 未作答 → 0 分，统一计入错误；
3. passageGroup 的题目逐题独立评分，材料音频不计分；
4. 汇总正确数、错误数（= 总数 - 正确数）、正确率；
5. 固化到报告，状态改为 `READY`；
6. 评分重试幂等，同一 Attempt 只产生一份 Report。

**三层逻辑**：
- **Service**：`ListeningScoringService.evaluate(Long recordId, Long reportId)`，逐题比对 `PracticeAnswer.answer` 与 `standardAnswerSnapshot`，写入 `isCorrect`/`points`，汇总后更新 `PracticeReport`。
- **实现方式**：可在 `ListeningReportServiceImpl` 内同步完成，或投递线程池/MQ 异步执行；幂等键 = `(recordId, reportId)`。
- **Mapper**：`PracticeReportMapper.updateReportStatus + updateScore`、`PracticeAnswerMapper.updateIsCorrectAndPoints`（XML 批量）。

## 六、关键业务约束

| 约束 | 说明 |
|---|---|
| **答案隔离** | 作答阶段所有接口**绝不返回**标准答案（`correct`）、解析、音频文字稿（`audioText`）、字幕、译文；仅在单题回顾接口返回 |
| **报告二值化** | 报告只有"正确""错误"两种结果；未作答统一计入错误，不单独展示未作答数 |
| **播放速度不入库** | 1x/0.5x 是客户端本地偏好，不进入服务端任何接口或数据库字段 |
| **自动播放** | 客户端进入题目后 ~1.2s 自动播放音频，纯客户端行为，服务端不感知 |
| **passageGroup 导航** | 题号命中共同材料音频范围时，材料音频固定在页面上方，题目在下方逐题切换；是否命中范围由「等级+题号」判定，详见 2.3 |
| **幂等提交** | 同一 `recordId + idempotencyKey` 重复提交始终返回同一 `reportId`，不生成第二份 Report |
| **快照不可变** | 提交时固化的题目/素材/评分规则版本在报告中不可修改；CMS 后续修题不影响历史报告 |
| **乐观锁冲突** | 多端同时修改同一草稿时返回冲突摘要，不自动合并，由用户选择保留本机或云端版本 |
| **音频鉴权** | 所有音频 URL 使用短期签名（1-2小时），不暴露永久裸链 |
| **材料音频复用** | 一段 `share_audio_url` 可被同一题号范围内的多道题目共享，但每道题仍是独立计分题；共享范围由「等级+题号」判定（HSK4:36-45、HSK5:31-45、HSK6:16-50） |
| **草稿保留期** | 默认 90 天，与其他真题练习模块一致 |

## 七、与阅读模块的核心差异

| 维度 | 阅读模块 | 听力模块 |
|---|---|---|
| 素材类型 | 纯文本 | 音频 + 文本 + 图片 |
| 题型布局 | 单一文本选择 | 6 种布局（imageJudge/textJudge/imageChoice/imageMatch/textChoice/passageGroup） |
| 音频下发 | 无 | 需返回题目音频和材料音频，带版本和签名 |
| 拼音支持 | 无 | HSK1-2 文本选项可带拼音（ruby 注音） |
| 答案格式 | 文本选项 ID | 文本/图片选项 ID，判断题用 `true`/`false` |
| 播放控制 | 无 | 服务端不处理播放状态（纯客户端行为），播放次数由等级配置决定（HSK1-4 为 2，HSK5-6 为 1） |
| 题组结构 | 无 | passageGroup：材料音频 + 多道题目，逐题切换 |
| 报告回顾 | 文本+选项 | 额外含音频回放，按"材料→题目→图片→选项"层级展示 |
| 内容隔离 | 答案+解析 | 额外隔离音频文字稿（`audioText`）、字幕、译文 |
