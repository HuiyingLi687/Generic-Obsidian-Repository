# 全面提升课需要的内容

> 依据：`全面提升课_v1.5_文档与原型/汉考宝全面提升课_PRD与原型_v1.5`（PRD v1.5 + 原型图 Q01–Q81）
> 逐条形式编号（Q01–Q81）见 [[全面提升课固定形式清单]]

## 一、界面布局 `course_layout`

全面提升课自建一套，**不与考试侧 `exam_layout`、练习侧 `question.layout` 混用**：

1. 考试侧 8 值按**判分口径**划（`multiChoice`、`passageChoice` 都在服务判分），提升课不判分，口径不同。
2. 练习侧 `question.layout` 有 8 个老值 + 48% NULL，practice-service 4 处依赖，动它就是改存量。
3. 三套若共用常量，任一方加值或改名都会牵连另外两处。

`course_layout` 只描述**作答动作**，不描述材料媒介、篇幅长短、左右栏形态。**7 个值**：

| 值 | 作答动作 | 渲染要点 |
| --- | --- | --- |
| `choice` | 从选项里选一项 | 选项 2–5 项，媒介由哪列有值决定；有材料时材料与题干同屏；共享听力材料（Q73、Q74）需同时渲染共享音频与单题音频两个播放键 |
| `judge` | 两项判断 | 选项固定两项，沿用已配置文案 |
| `pair` | 左右两栏配对 | 左序号 1/2/3，右字母 A/B/C，点左再点右；左右栏是文字还是音频由字段决定 |
| `sharedAnswer` | 共享回答逐小题匹配 | 多问句共用一组回答，全答完才能提交 |
| `order` | 排序 | 点选追加、点已选撤回、必须用完；排序单位是词块或整句 |
| `write` | 文本写作 | 单行或多行输入 + 必用词 + 字数要求 |
| `record` | 录音作答 | 走录音练习状态机（A08） |

合并记录：`imageChoice` + `audioChoice` → `choice`，`audioPair` → `pair`，`sentenceWrite` + `passageWrite` → `write`。

### 三类差异不进 layout

它们都不改变用户的操作方式，改由字段表达：

| 差异 | 靠什么区分 | 同一 layout 下的例子 |
| --- | --- | --- |
| 选项媒介 | `option_content` / `option_image_urls` / `option_audio_urls` 哪列有值 | 听音选择（文字）、听音选图（图片）、看词选录音（音频）都是 `choice` |
| 配对栏媒介 | 左栏 / 右栏存的是文字还是音频 URL | 汉字与拼音配对、录音与词语配对都是 `pair` |
| 篇幅长短 | 字数上下限 | 看图用词造句（单句）与五词短文、阅读后缩写（成篇）都是 `write` |

### 41 个界面名称落在哪个值上

81 个形式全部有归属，无悬空。

| `course_layout` | 形式数 | 界面名称 |
| --- | ---: | --- |

## 二、材料字段（库表未建）

材料不占 `course_layout`，按槽位分列：

| 槽位 | 文字 | 音频 | 图片 |
| --- | --- | --- | --- |
| 题目题干 | `content` | `audio_url` | `image_urls` |
| 题目选项 | `option_content` | `option_audio_urls` | `option_image_urls` |
| 题组共享 | `passage` | `audio_url` | `image_urls` |

- 三列选项**互斥**：由 layout 决定哪列必填、其余必须为空，校验可写成 SQL 断言。
- 共享听力材料的两层音频都挂现成列：`question_group.audio_url`（整组一条）+ `question.audio_url`（每题一条）。
- 图片独立成列，**不许嵌在 HTML 里**，否则路径白名单只能正则扫。
