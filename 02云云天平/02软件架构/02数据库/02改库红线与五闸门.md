# 改库红线与五闸门

> 适用于所有写库脚本（`tmp/*.py`）。读库不在此限，但第四节的两条「读」的坑同样适用。
> 环境地址见 [[01开发环境与命令]] 第四节。

## 一、五闸门（写库脚本必须全过）

| 闸门 | 校验什么 | 不过就停 |
|---|---|---|
| **G1** | `SELECT DATABASE()` —— 确认连的是预期库 | 库名对不上 |
| **G2** | `SELECT @@hostname` —— 确认连的是预期机器 | 🔴 两个环境**库名都是 `xuexitest`**，只看库名分不出来 |
| **G3** | 备份 + 生成回滚 SQL | 无备份不写 |
| **G4** | 事务内回读核对（写完按条件反查） | 数量/值与预期不符就 `rollback` |
| **G5** | 幂等（重复执行结果一致） | 第二次跑出现变化即视为不幂等 |

默认 **DRY-RUN**，必须显式 `--apply` 才写库。

🔴 **备份的幂等写法反着来**：备份表/文件「已存在即跳过」，**不要覆写**。踩过两次 —— DRY-RUN 也会写备份，若用覆写，第二次幂等复跑会把第一次的备份冲成空表，等到真出问题已经没有干净数据。

## 二、DDL 的隐式提交

🔴 DDL 会**隐式提交**，`rollback()` 保不住。所以：

- 一个脚本里混了 `ALTER` + `UPDATE`，出错时 `UPDATE` 回滚不了
- 必须在 `except` 里**显式补偿**（把 DDL 反向执行）
- 断言 `ROW_FORMAT` 时先 `.upper()`，库里返回 `Dynamic` 不是 `DYNAMIC`

## 三、批量写库

| 坑 | 现象 | 对策 |
|---|---|---|
| `executemany` | 产生僵尸事务，报 `1205`（lock wait timeout） | **拼一条大 SQL** 执行 |
| 远端写库慢 | 客户端超时但事务还活着 | 放 `run_in_background`，别在前台等 |
| 僵尸事务残留 | 后续所有写入阻塞 | `SELECT * FROM information_schema.innodb_trx` 找到后 `KILL` |

## 四、读库两个必须知道的类型坑

### 4.1 `question.option_content` 是 `JSON` 列

🔴 `WHERE option_content = %s` **永远不命中**（JSON 比较不按字符串等值）。要改它：

```python
# 1) 加锁读出旧值
cur.execute("SELECT id, option_content FROM question WHERE id IN (...) FOR UPDATE")
# 2) Python 侧比对（不要指望 SQL 帮你判）
# 3) 回写用 json.dumps 默认格式（不要 sort_keys / 不要 separators）
cur.execute("UPDATE question SET option_content=%s WHERE id=%s", (json.dumps(obj, ensure_ascii=False), qid))
```

### 4.2 `question` 表**没有 `updated_at` 列**

备份 SELECT 里写 `updated_at` 直接 `1054`（好在写库前中止，不会污染）。类似的还有 `created_at` —— 实际列名是 `created_time` / `updated_time`。

## 五、TEST ≠ PROD

**任何时候判断前都要两个环境都查一遍**，不能拿 TEST 的结论直接推 PROD。已踩过的实例：

| 项 | 曾经的差异 |
|---|---|
| `science_chinese` 结构行 | PROD 缺（后补 8103） |
| `user_exam_quota` CSCA | PROD **0 行** → 全员 8105（后补 8105） |
| `csca_question_favorite` / `_wrong` | PROD 缺表 |
| `practice_record.question_ids` | PROD 缺列 → 建轮 INSERT 报 `Unknown column` → 前端「系统错误」 |

### 5.1 上线前必做结构 diff

```bash
# 已有工具（只读）
java tmp/FullSchemaDiff.java    # 全表结构对比
java tmp/TypeDiff.java          # 字段类型/长度对比
```

🔴 **「代码上线了，DDL 忘在 PROD」是最常见的生产事故形态**，而且不重启也生效（加列即生效），容易误判成代码问题。

## 六、CSCA 入参值域（写库/调接口前先看）

| 参数 | 只认 | 传错的表现 |
|---|---|---|
