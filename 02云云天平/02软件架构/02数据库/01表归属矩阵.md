# 表归属矩阵

73 张表按服务归属。用途只有一个：**改表之前，先知道会影响到谁。**

数据来源：代码中 `@TableName` 注解反查，`grep -rho '@TableName("[^"]*")' --include="*.java" <模块>`。

## 一、共用表：改动需协同上线（10 张）

这些表被多个服务引用，加字段、改类型、改语义时，**所有引用方必须一起上线**，否则会出现「A 服务写入新字段、B 服务读旧结构报错」。

| 表名                             | 引用服务                                 | 影响面        |
| ------------------------------ | ------------------------------------ | ---------- |
| `exam_paper`                   | exam-service、manage、practice-service | **高（3 方）** |
| `speaking_exam_paper`          | exam-service、manage、practice-service | **高（3 方）** |
| `speaking_exam_paper_question` | exam-service、manage、practice-service | **高（3 方）** |
| `product`                      | manage、pay-service                   | 中（2 方）     |
| `sku_price`                    | manage、pay-service                   | 中（2 方）     |
| `question_shared_audio`        | manage、practice-service              | 中（2 方）     |
| `hsk_level_config`             | exam-service、practice-service        | 中（2 方）     |
| `user`                         | auth-service、user-service            | 中（2 方）     |
| `user_exam_quota`              | auth-service、exam-service            | 中（2 方）     |
| `study_abroad_consultation`    | manage、system-service                | 中（2 方）     |

## 三、维护规则

1. **新增表时必须在此登记**，写在对应服务的清单里，并注明归属；否则三个月后没人知道这张表是谁的
2. **新增跨服务引用时，把表移入第一节共用表**，否则下次改表会漏掉一个服务
3. **删表时不要直接删除条目**，改为删除线并注明日期与替代方案，保留可追溯性
4. 本文件与代码不同步时，**以代码为准**，并回来修正本文件
