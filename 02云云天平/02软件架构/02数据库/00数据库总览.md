# 数据库总览

汉考宝（`hsk_treasure`）数据库的事实与迁移机制入口。读完这篇应该能回答三个问题：库在哪、表归谁管、改表怎么上线。

## 一、基本事实

| 项 | 值 |
|---|---|
| 数据库 | MySQL 8.0 |
| 库名 | `xuexitest` |
| 表数量 | **73 张**（按代码 `@TableName` 统计，不含未映射的历史表） |
| 模块数 | 11 个，其中 8 个直接读写数据库 |
| 代码仓库 | `D:\code\hsk_treasure` |

### 环境地址

| 环境      | 地址                            | 配置来源                          |
| ------- | ----------------------------- | ----------------------------- |
| 生产 PROD | `43.99.57.11:3306/xuexitest`  | 各服务 `application-prod.yml`    |
| 测试 TEST | `8.138.185.11:3306/xuexitest` | 各服务 `application-test.yml`    |

同一套表结构跑在两个地址上，**任何一次结构变更都要在这几处保持一致**，这是漏迁移的直接原因。

## 二、最大的结构性风险：11 个服务共用一个库

微服务的常规做法是「一个服务一个库」，这里是「11 个服务一个库」。这带来两个后果：

**后果一：改一张表可能同时影响 3 个服务**

`exam_paper` 被 `exam-service`、`manage`、`practice-service` 三方引用；`speaking_exam_paper` 和 `speaking_exam_paper_question` 同样如此。加一个字段、改一个类型，三个服务的实体类都得跟着动，上线也必须一起上。

**后果二：迁移脚本不能由服务自己执行**

如果每个服务内嵌 Flyway，同一份脚本会被执行 11 次，第二次开始就报 `Duplicate column`。所以迁移必须是**独立的一个动作**，在业务服务启动前完成。

完整表归属见 [[01表归属矩阵]]。

## 三、当前迁移机制的现状

改表的脚本散落在三个地方，没有一个参与部署流程：

| 位置 | 数量 | 入库 | 参与部署 |
|---|---|---|---|
| `sql/`（init + 增量） | 4 | 是 | 否，在仓库根，不进任何镜像 |
| `*/src/main/resources/db/` | 20 | 是 | 仅 practice 通过 `docker-entrypoint-initdb.d` 生效，且只在**空库首次初始化**时执行 |
| `tmp/` | 141 | **否** | 否，手工执行 |

`tmp/` 里 128 个是回滚脚本，命名带 `PROD` / `TEST` 和时间戳，说明操作纪律是好的，但**这批文件完全未被 git 跟踪**（`git ls-files tmp/` 为 0），只存在于一台机器上。

部署动作是「重新打镜像 → `docker compose up`」，它只读 `src/` 和 `pom.xml`，**三个 SQL 位置一个都不碰**。这就是「代码合并了、数据库没迁」的机制成因。

## 四、目标机制

```
代码仓库                          本 vault
db/migration/                    02数据库/
├── V1__baseline.sql             ├── 00数据库总览.md       ← 本篇，事实
├── V2__xxx.sql                  ├── 01表归属矩阵.md       ← 表归谁管
└── V3__xxx.sql                  ├── 02变更台账.md         ← 业务意图
                                 └── 03数据库迁移规范.md   ← 怎么改、怎么上线
```

**三处分工，互不重复：**

| 问题 | 答案在哪 |
|---|---|
| 线上到底执行了哪些脚本 | 查 `flyway_schema_history` 表（唯一事实来源） |
| 这次改了什么、怎么执行 | `db/migration/V*.sql`，含四行头部注释 |
| 为什么要改、影响哪些业务 | [[02变更台账]] 一行记录 |
| 这张表归谁管 | [[01表归属矩阵]] |

Obsidian 里**不放 SQL 正文**。SQL 是机器执行的资产，必须跟代码同仓同提交；搬进 vault 只会变成双份维护，必然脱节。
