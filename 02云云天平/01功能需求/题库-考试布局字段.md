# 题库-考试布局字段

## 背景

前端渲染一道题时，需要先知道「这题长什么样」才能选控件：单选框？复选框？按序点选？输入框？录音？
现在只能靠题型编码 + 内容嗅探（有没有 `<img>`、有没有 `<p>`、选项几个）去猜，猜错就是显示错乱或控件缺失。

**目标**：库里存一个「控件枚举」，前端拿到直接选渲染分支，不再猜。

## 用户看到什么

1. 同一种控件形态的题，不管内容是文字还是图片，界面表现一致；
2. 41 个题型编码全部有明确控件，没有「未知题型」兜底页；
3. 例题与正题用同一套渲染，只是不计分。

## 什么算对（验收标准）

| # | 判据 |
|--:|---|
| 1 | 全库 13,524 题（HSK 11,620 + CSCA 1,904）零落空，没有 null |
| 2 | 值域恰好 8 个，不接受自由文本 |
| 3 | 一个值 = 一个作答控件，与「内容是文字还是图片」无关 |
| 4 | 值里不含音频来源、不含变体（short/long/interview）、不含是否计分 |

## 值域（8 个，v3.8 定稿）

| 大类 | 值 | 中文 | 题量 |
|---|---|---|---:|
| 点选类 | `choice` | 单选（文字/图片/字母） | 10,089 |
| | `imageMatch` | 图片匹配（图池取一） | 920 |
| | `multiChoice` | 多选 | 35 |
| | `judge` | 判断 √/× | 1,150 |
| | `passageChoice` | 材料题（分栏） | 178 |
| 排序与作答 | `order` | 点选排序（句子/词） | 749 |
| | `input` | 文本作答（字/句/文/译） | 396 |
| | `record` | 录音作答（口语/口译） | 7 |

演化过程（为什么只剩 8 个）：文字/图片不参与分族 → 判断合 1、选择合 1、选句填空并入选择、排序合 1、写与译并入输入、单字曾拆出又回滚、口译并入录音。

## 已知约束

- 🔴 **不能复用 `question.layout`** —— 那是练习侧在服役的老字段（8 个老值、48% 为空），
  改它会让听力细节题丢共享音频。字段现状见 [[00字段红线索引]] §三。
- 🔴 布局值只管渲染，**不应据此判分**；需要字数提示、提示语的，仍看 `type_id_mapping`。
- 例题不是布局值，是题型；它的布局取「同卷同题号区间内正题的众数」。
