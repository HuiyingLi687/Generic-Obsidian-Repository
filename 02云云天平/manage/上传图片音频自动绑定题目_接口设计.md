> 适用服务：`manage`（直连端口 8085；经网关访问需加 `/api` 前缀，见下文"访问路径"）
> 关联需求：`上传图片自动绑定题目.txt`
> 关联实体：`Question`（`question` 表）、`QuestionGroup`（`question_group` 表）、`ExamPaper`（`exam_paper` 表）
> 版本：v7（2026-09-03 修订，草稿待评审）
>

>
> v6 变更：**回退为「纯新增」语义**——上传接口不再做任何查重/增量补图/覆盖判断，重复导入同一试卷即重复新增（与既有 `upload/hsk` 行为一致），接口保持简洁。移除 `override` 参数、`imageSkipCount` 字段，以及「目标已存在图片链接→跳过/覆盖」的整套查重逻辑（含题组区间变化报错）。

>
> v4 变更：落地「增量补图」——**已于 v6 回退，不再保留**。
>
> v3 变更：落地「目标已存在图片链接」查重规则——**已于 v6 回退，不再保留**。
>
> v2 变更：① 无选项图由「追加到 `passage` 末尾」改为「**图片在题目内容前**」；② 新增**题组**规则——「题目序号」为空时图片落 `question_group.passage`（图在文章内容前）；③ 去除「按名校核交叉校验」；④ 明确例题（序号 `0`）属单题，不走题组逻辑；⑤ 明确**题组行不含有选项图**（2026-09-02 确认）。

## 1. 接口概述

该接口用于**一次性同时上传一份 Excel、若干图片、以及（可选）一份完整听力音频**，系统解析 Excel 中每道题的「图片名称」列，并按统一命名模板把图片链接自动写入题目的对应字段；若传入了音频，则把音频 URL 写入试卷下所有听力题组的 `audio_url`：

- 图片文件名含选项后缀（`_A`~`_F`，或例题形式 `例A`~`例F`）→ 写入 `question.option_content` 对应选项的图片 HTML。
- 图片文件名不含选项后缀（如例题序号 `例1`）→ 写入 `question.passage`，**图片链接放在已有「题目内容」之前**（题目内容可为空）。
- 若该行「题目序号」**为空**（属**题组**）→ 图片写入 `question_group.passage`，**图片链接放在已有「文章内容」之前**。
  （**题组行不含有选项图**，其「图片名称」列只可能出现题干/篇章图，一律落 `question_group.passage`，不走 `option_content`。）
- 若传入了 `audio`（完整听力音频）→ 上传到 MinIO 得 URL，写入该试卷下**所有** `section_mapping=SEC_LISTEN` 的 `question_group.audio_url`（**整卷一份音频**，所有听力题组共用）。

Excel 每行即一道题（或一组同序号题），「图片名称」列列出该题对应的图片（可多张，逗号分隔）。文件名结构仅用于**判断图片应绑到哪个字段**（选项图 `option_content` 或篇章 `passage`），不用于题号校验——图片绑定的正确性由 Excel 内容保证（见下方人工检查约定）。

## 2. 请求定义

### 2.1 基本信息

| 项 | 值 |
|---|---|
| 路径 | `POST /question/upload/hsk/with-media` |
| 方法 | POST |
| Content-Type | `multipart/form-data` |
| 鉴权 | 需 `X-Client-Type: ADMIN` + `Authorization: Bearer <JWT>`（直连单服务时，若无登录态见"本地调试说明"） |

> 说明：现有 `POST /question/upload/hsk` 仅接收 Excel（`file` 参数）。本接口在其基础上**新增 `images` 多文件部分与可选 `audio` 音频部分**，保持向后兼容——不传 `images` 时退化为原有纯 Excel 导入行为；不传 `audio` 时仅做图片绑定。

### 2.2 请求参数

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `file` | form-data | File (xlsx) | 是 | 题目 Excel，列结构见第 6 节 |
| `images` | form-data | File[] (多个) | 是 | 本次导入涉及的全部图片文件（多 part 同名 `images` 上传） |
| `audio` | form-data | File | 否 | 完整听力音频（mp3/wav/ogg/m4a/flac）；传入则绑定到试卷下所有 SEC_LISTEN 题组的 `audio_url` |

**访问路径（重要）**：
- 经网关：`http://<gateway>/api/question/upload/hsk/with-media`
- 直连 manage（如本地断网）：`http://localhost:8085/question/upload/hsk/with-media`
- 注意：直连时网关不加 `/api`，路径里没有 `/api`。

## 3. 图片命名规范（解析依据）

统一模板（与 txt 一致）：

```
HSK{级别}_{试卷编号}_{定位信息}[_{选项}]
```

| 部分 | 说明 | 示例 |
|---|---|---|
| 级别 | HSK1–HSK6 | `HSK1` |
| 试卷编号 | 试卷编号（如从「来源」`HSK1_H11112` 取 `11112`） | `11112` |
| 定位信息 | 题号 / 题号范围 / 题型范围+例序号 | `6` / `1-5` / `1-5_例1` |
| 选项（可选） | 选项字母 A–F；例题的选项图形如 `例A`~`例F` | `_A` / `_例A` |

**示例文件名**：
- `HSK1_11112_6_A.jpg` → 级别 HSK1，试卷 11112，题号 6，选项 A
- `HSK1_11112_1.jpg` → 级别 HSK1，试卷 11112，题号 1，无选项
- `HSK1_1-5_例1.jpg` → 级别 HSK1，定位 `1-5_例1`（例题），无选项 → 落 `passage`
- `HSK1_6-10_例A.jpg` → 级别 HSK1，定位 `6-10_例A`（例题选项 A）→ 落 `option_content.A`

> ⚠️ Excel 实测：「图片名称」列**可含多张图片，逗号分隔**，例如：
> `HSK1_11112_6_A.jpg,HSK1_11112_6_B.jpg,HSK1_11112_6_C.jpg`
> 接口必须按逗号拆分后逐张处理。

## 4. 绑定规则

逐张图片解析文件名（取去掉扩展名后的主体，按下划线 `_` 分段，取**最后一段**判断）：

### 规则 1：含 `[_{选项}]` → 绑到 `question.option_content` 对应选项

格式（与 txt 一致）：

```json
{
  "A": "<img src=\"<图片URL>\" style=\"max-width:100%;\">",
  "B": "<img src=\"<图片URL>\" style=\"max-width:100%;\">",
  "C": "<img src=\"<图片URL>\" style=\"max-width:100%;\">"
}
```

- 当文件名最后一段为单个字母 `A`–`F`，或形如 `例A`~`例F`（例题的选项图）时命中此规则；提取其中的选项字母（`A`~`F`）作为 key。
- 多张同选项图片 → 同一选项值内**拼接**（追加 `<img ...>`）。
- 未在该题「题目选项」中出现的选项字母 → 记为告警，不写入。

### 规则 2：不含 `[_{选项}]` → 绑到 `question.passage`（图片在「题目内容」**之前**）

适用：该行「题目序号」**非空**（含例题的 `0`）。

> ⚠️ `passage` 字段本身已存有「题目内容」，**图片链接必须放在题目内容之前**；题目内容可以为空。

格式（与 txt 一致）：

```html
<img src="<图片URL>" style="max-width:100%;">题目内容...
```

实例（来自 txt）：

```html
<img src="http://www.hkbvvtb.com:9000/hsk/image/3232344/hsk-2062042676694003713/HSK5_51002_100-7ed70ef9-7184-4468-8e2e-972a8ff30537.jpeg" style="max-width:100%;">请根据这张图片写一篇80字左右的短文.
```

- 末段为 `例1`/`例2` 等例题序号（非选项字母）→ 落入 `passage`（例题图）。
- 末段为 `X`/`AB` 等非 `A`~`F` 且非 `例A`~`例F` → 视为无选项，落入 `passage`。
- 多张无选项图片 → 在「题目内容」前**顺序拼接**多张 `<img>`，再接题目内容。

### 规则 3：「题目序号」为空（题组）→ 绑到 `question_group.passage`（图片在「文章内容」**之前**）

适用：该行「题目序号」**为空**（`isBlank`），这类行属**题组**（一组题共享的文章）。

> ✅ 已确认（2026-09-02）：**题组行不含有选项图**。题组行的「图片名称」列只会出现题干/篇章图，一律按本规则落 `question_group.passage`；**不判断选项字母、不写 `option_content`**。
> 若题组行意外出现末段为 `A`~`F` / `例A`~`例F` 的图片名，属 **Excel 数据异常**（命名写错），记 warning 提示人工核查，仍**不**写入 `option_content`。

> ⚠️ `question_group.passage` 字段本身已存有「题目文章内容」，**图片链接必须放在文章内容之前**。

格式（与 txt 一致）：

```html
<img src="<图片URL>" style="max-width:100%;"><p>文章内容</p>...
```

实例（来自 txt，后文略）：

```html
<img src="http://www.hkbvvtb.com:9000/hsk/image/3232344/hsk-2062042676694003713/HSK5_51002_71-74-e9c288d5-72bb-42ea-aef5-27f417b30b89.png" style="max-width:100%;"><p>一直以来,"80后"这个词儿都含有年轻的味道.随着时间的流逝,我们突然发现,第一批"80后"--1980年出生的人,已经步入而立之年了.</p><p>…</p>
```

- 多张无选项图片 → 在「文章内容」前顺序拼接多张 `<img>`，再接文章内容。
**实现说明（为什么不用新分支）**：题组行在 Excel 里只有一行，其「题目内容」列**本身就是那篇共享文章**，解析后暂存在 `Question.passage`；该 `Question` 只是**临时载体、不入库**——`QuestionGroupServiceImpl.uploadGroupQuestions` 会把它的 `passage` 搬进 `QuestionGroup.passage`，然后把 `question.passage` 置空，再按题号区间拆出 N 道子题（子题 `passage` 均为 `null`）。

因此「题组行的 `question.passage`」与「`question_group.passage`」**不是两份不同内容**，而是同一份内容搬家前/后的两种状态。图片功能**只做一件事**：把图片拼进 `eo.passage` 前面；后续的「复制 + 置空」是既有流程对所有题组行一视同仁的行为（与是否导入图片无关），无需为图片新增任何分支。

#### 拆出的 N 道子题，各字段从哪来？

| 子题字段 | 值 | 来源 |
|---|---|---|
| `passage` | **恒为 `null`** | 文章不属于任何单道子题，只在 `question_group.passage` 存一份 |
| `group_id` | 指向所属 `QuestionGroup.id` | 子题凭此关联取文章（`uploadGroupQuestions` 第 155 行设置） |
| `content`（题干） | 各自一份 | Excel「题目标题」列按 `---` 拆分后按序取 |
| `option_content` | 各自一份，或 `null` | 取决于是否共享选项（见下） |
| `answer` / `score` | 各自一份 | Excel「答案」「分值」列按 `,` 拆分后按序取 |

> 关于共享选项：`needAddToGroup = (选项按 --- 拆分后只有 1 份)`。为 `true` 表示整组共用一套选项（如听力判断 `A:√, B:×`），此时选项与 `content` 都存放在 `question_group` 上，子题为 `null`；为 `false` 表示每道题选项不同，则各子题分别持有自己的 `option_content` 与 `content`。
> **无论哪种情况，`passage` 都归 group，子题恒为 `null`** —— 这是"大题分组"的既有设计，不是图片功能引入的。

### 绑定到"哪道题"（落点判定）

先按该行「题目序号」是否为空，决定图片落在**题目**还是**题组**：

| 该行「题目序号」 | 归类 | 无选项图落点 | 选项图落点 |
|---|---|---|---|
| 非空（含例题的 `0`） | 单题 / 例题 | `question.passage`（规则 2） | `question.option_content`（规则 1） |
| 为空 | 题组 | `question_group.passage`（规则 3） | **不存在**（题组行不含选项图，见规则 3） |

- **按行绑定（唯一方式）**：Excel 每行自身的「图片名称」即该题/该组的图片清单，直接绑到本行解析出的题目（由「试卷编号 + 题目序号」定位 `paper_id` 与 `number`）。**不做跨字段交叉校验**——不拿文件名里的题号/定位信息去和行内字段比对。
- 若 Excel「图片名称」列填错（如填了别的题/别的字段的文件名），属 **Excel 内容问题**，由人工检查 Excel 发现，接口不额外校验；图片名称里引用的文件未在 `images` 中上传时，仍按既有规则记 warning 跳过。
- **例题行**（定位信息如 `1-5_例1`，题目序号为 `0`）：序号**非空** → 归"单题"，落 `question.passage` / `option_content`，**不走题组逻辑**。
- **题组行**（题目序号为空）：无选项图落 `question_group.passage`；这类行在既有导入逻辑中本就进 `uploadGroupQuestions` 归组处理。

## 5. 处理流程

```
1. 接收 multipart：file(Excel) + images[](多张) + audio(可选)
2. 解析 Excel → List<Row>；每行含 图片名称(可逗号多值)
3. 逐张上传 images → MinIO，得到 URL；建立 map: 文件名(stem) → URL
4. 遍历 Excel 行：
   a. 组装/匹配 ExamPaper：用 来源(HSK1_H11112) 或 图片名试卷编号 解析出 试卷编号，
      匹配 exam_paper.source/version/level，不存在则新建
   b. 解析本行题目字段（见第 6 节映射），生成/定位 Question（paper_id + number）
   c. 拆分 图片名称 为多文件名，逐张判定落点（题组行不含选项图，不判选项字母）：
      - 本行题目序号为空（题组）    → passage = <img>... + 文章内容（图在前）
                                      ↓ 由 uploadGroupQuestions 复制到 question_group.passage（规则 3）
      - 序号非空 且 末段 ∈ [A-F] / 例[A-F] → question.option_content[letter] += <img>（规则 1）
      - 序号非空 且 无选项          → question.passage = <img>... + 题目内容（图在前，规则 2）
   d. 若图片在 images 中未上传 → 记 warning，跳过该图
5. 批量保存 Question / ExamPaper / QuestionGroup
6. 若传入 audio：
   a. 上传 audio → MinIO（audio/{userId}/hsk-{paperId}/{文件名-uuid}.ext），得到 URL
   b. 查询 question_group：paper_id = 本试卷 且 section_mapping = SEC_LISTEN
   c. 所有命中题组统一 setAudioUrl(URL)，updateBatchById（整卷一份音频）
7. 返回结果：题目数、上传图片文件数、上传音频文件数、音频绑定题组数、告警列表
```

## 6. Excel 列 → 实体字段映射

| Excel 列 | 必填 | 映射到 | 说明                                 |
|---|---|---|------------------------------------|
| 考试大纲* | 是 | `exam_paper.version` | 如 `HSK2.0`                         |
| 学科类型(HSK非必填) | 否 | `exam_paper.subject_type` / `question.type_id_mapping` | 如 `听力:判断`                          |
| 题型* | 是 | `question.type_id` / `type_id_mapping` | 如 `1`                              |
| 一级标题* | 是 | `question.title1_text` | 如 `听力`                             |
| 一级标题内容* | 是 | `question.title1_number` | 如 `1`                              |
| 部分标题* | 是 | `question.section` | 如 `例题` /如 `1-5`                    |
| 题目分组(或者范围)* | 是 | `question.question_group` | `第 1-5 题…`                         |
| 部分标题内容 | 否 | `question.section_title` |                                    |
| 题目序号 | 否 | `question.number` (String) | 如 `0`/`1`；**为空则本行属题组**，无选项图落 `question_group.passage` |
| 题目标题 | 否 | `question.content` | 注：实体中 `content`=题目标题               |
| 题目内容 | 否 | `question.passage` | 实体中 `passage`=题目内容；**非选项图片的落点，图片在内容前**（规则 2） |
| 题目内容（仅题组行，序号为空） | 否 | `question_group.passage` | 题组文章内容；**非选项图片的落点，图片在内容前**（规则 3） |
| 题目选项 | 否 | 选项文本（用于校验选项字母）；图片锚定写入 `option_content` | 如 `A:√,B:×` / `A,B,C`              |
| 答案* | 是 | `question.answer` | 如 `A`                              |
| 分值* | 是 | `question.score` | 如 `5`                              |
| 来源* | 是 | `exam_paper.source` | 如 `HSK1_H11112`（据此解析试卷编号）          |
| 等级* | 是 | `exam_paper.level` | 如 `1`（HSK 等级）                      |
| 图片名称 | 否 | 触发图片绑定（见第 3、4 节） | 可逗号多值                              |

> 注意区分两个易混字段：
> - Excel「题目选项」= 选项**文本**；
> - DB `option_content` = 图片锚定的 **JSON**（规则 1 的结构）。
> 处理时由「题目选项」校验选项合法性，由 `option_content` 承载图片 HTML。

## 8. 响应示例

```json
{
  "code": 0,
  "message": "成功导入 30 题，上传图片 42 张，上传音频 1 个",
  "data": {
    "questionCount": 30,
    "imageCount": 42,
    "audioCount": 1,
    "audioGroupBindCount": 3,
    "imageBindCount": 40,
    "warnings": [
      "图片未上传，已跳过: HSK1_11112_12_D.jpg",
      "图片 HSK1_11112_18_X.jpg 选项 X 不在本题选项内，已忽略"
    ]
  }
}
```

> 字段说明：
> - `imageCount`：**实际上传成功的图片文件数**（非绑定到题目的图片链接条数）。
> - `audioCount`：**实际上传的音频文件数**（0 或 1）。
> - `audioGroupBindCount`：音频实际绑定到的听力题组数（辅助信息，未传 `audio` 时为 0）。
> - `imageBindCount`：图片实际绑定到题目的条数（选项图 + 篇章图，每张成功匹配上传列表的图片各计一次）。
> - 未传 `audio` 时 `audioCount` 为 0，`message` 不含「上传音频」片段。

## 9. 边界情况与错误处理

| 场景 | 处理 |
|---|---|
| 图片名称含多张（逗号分隔） | 拆分逐张处理 |
| Excel 引用了某图片但 `images` 中未上传 | 记 warning，跳过该图，不中断整体导入 |
| 文件名末段为 `例A`~`例F` | 例题的选项图，提取字母后落入 `option_content` 对应选项 |
| 文件名末段为 `X`/`AB`/`例1` 等非选项字母 | 视为无选项，落入 `passage` |
| 选项图片字母不在本题「题目选项」内 | 记 warning，忽略该绑定 |
| 同一选项多张图片 | `option_content[letter]` 内拼接多个 `<img>` |
| 同一题目多张无选项图片（序号非空） | `question.passage` 内，在「题目内容」**前**顺序拼接（规则 2） |
| 题组行（序号为空）多张无选项图片 | `question_group.passage` 内，在「文章内容」**前**顺序拼接（规则 3） |
| 行「题目序号」为空（题组） | 图片一律 → `question_group.passage`（图在前）。**题组行不含选项图**；若出现 `A`~`F`/`例A`~`例F` 结尾的图片名，记 warning 提示 Excel 数据异常，仍不写 `option_content` |
| 传入 `audio` 但音频 MIME 不支持 | 抛 `FILE_UPLOAD_MIME_ERROR`，报错信息含「文件名 + Content-Type + 扩展名 + 支持列表」（如 `音频文件「xxx.xx」格式不支持：Content-Type=...，扩展名=...。仅支持 mp3 / wav / ogg / m4a / flac`），整个导入事务回滚 |
| 传入 `audio` 但试卷下无 SEC_LISTEN 题组 | 抛 `QUESTION_NOT_FOUND`「未找到该试卷下 section_mapping=SEC_LISTEN 的听力题组」，整个导入事务回滚 |
| 重复导入同一试卷 | **纯新增**——不做查重，重复导入即重复建题/建题组（与既有 `upload/hsk` 行为一致）；`audio_url` 覆盖式写入 |
| 试卷（`source`+`version`+`level`）不存在 | 自动新建 `exam_paper` 并回填 `paper_id` |
| `created_by` 为空（无登录态直连） | 见"本地调试说明"；生产经网关必带登录态 |

## 10. 与现有接口的关系

- 现有 `POST /question/upload/hsk`（`file` 单参数）保持不变；本接口为其**超集**，新增 `images` 多文件与可选 `audio` 音频。
- 现有 `POST /file/uploadImage`（单图上传，返回 URL）可作为图片上传的底层能力被本接口复用（批量上传图片 → 取 URL → 绑定）。
- 前端「上传题目资料」页面建议直接调用本接口，一次提交 Excel + 图片 +（可选）音频。

## 12. 实现说明（代码落地）

接口已在 `manage` 模块落地，改动点：

- `QuestionController`：新增 `POST /question/upload/hsk/with-media`（`file` + `images[]` + 可选 `audio`）。
- `QuestionExcelEo`：新增 `imageName` 字段（`@ExcelProperty("图片名称")`），读取 Excel 图片名称列（可逗号多值）。
- `HskExcelHandler.bindImages`：在 `convertOptionContent` 解析完选项后，按图片名称把图片链接合并进 `option_content`（选项图）或 `passage`（篇章图，**图在前**）；通过 `ThreadLocal<ImageBindContext>` 隔离请求，**普通 `upload/hsk` 流程不受影响**。
  - 题组行（「题目序号」为空）**不判选项字母**，图片一律前置拼进 `eo.passage`；**仅此一步**。后续由 `QuestionGroupServiceImpl.uploadGroupQuestions` 第 140 行 `questionGroup.setPassage(question.getPassage())` 搬进 `question_group.passage`，第 154 行 `question.setPassage(null)` 清空载体——这是既有流程（对所有题组行生效），**图片功能未新增任何复制/置空代码**。
  - 注意：题组行这个 `Question` 对象**不会入库**（`uploadGroupQuestions` 只返回拆出的子题），入库的是 `QuestionGroup` + N 道子题。
- `QuestionServiceImpl.uploadHskWithMedia`：先用 `MinIOUtils` 批量上传图片，建立 `文件名(stem)→URL` 映射，注入 handler 上下文，再走原 `processUpload`（建试卷/题目/题组）；`processUpload` 返回后，若传入了 `audio`，从 `resultEo` 首行解析出 `paperId`，调用 `QuestionGroupService.bindListeningAudio` 完成听力音频绑定；返回 `UploadWithImagesResult`（题目数 / 上传图片文件数 / 上传音频文件数 / 音频绑定题组数 / 告警）。
  - 注入 `QuestionGroupService` 使用 `@Lazy`（与 `QuestionGroupServiceImpl` → `QuestionService` 的 `@Lazy` 互相配对，避免循环依赖）。
- `QuestionGroupService` / `QuestionGroupServiceImpl`：新增 `bindListeningAudio(Long paperId, MultipartFile audio)`——上传音频到 MinIO（`audio/{userId}/hsk-{paperId}/`），查询该试卷下所有 `section_mapping=SEC_LISTEN` 的 `question_group`，统一 `setAudioUrl` + `updateBatchById`，返回 `ListeningAudioBindResult`（audioUrl / groupBindCount）。
- 新增 DTO `UploadWithImagesResult`（`questionCount` / `imageCount` / `audioCount` / `audioGroupBindCount` / `imageBindCount` / `warnings`）、`ListeningAudioBindResult`（`audioUrl` / `groupBindCount`）。

> 说明：本接口为**纯新增**语义——每次上传都照常新建题目/题组，**不做查重、不做增量补图、不做覆盖判断**，与既有 `upload/hsk` 行为完全一致，仅额外多了「图片绑定 + 音频绑定」两步。重复导入同一试卷会产生重复数据，属预期行为（由调用方自行保证不重复导入）。音频 `audio_url` 为覆盖式写入（重传即覆盖）。
