# 错误码规范

> 适用范围：所有对外接口的统一返回体。核心原则：**错误码按模块分段、枚举按模块隔离**。

## 一、错误码分段登记

| 段位        | 归属               |
| --------- | ---------------- |
| 4xx / 5xx | 通用语义（参数、认证、系统异常） |
| 10xxxx    | 模块1              |
| 12xxxx    | 模块2              |
| 13xxxx+   | 待分配，新增模块在此表登记    |

- 通用段沿用 HTTP 语义码值（400 / 401 / 403 / 404 / 500），便于前端和网关统一识别，**不在此段放业务错误**。
- 业务错误一律使用六位码，前两位为模块号，后四位为模块内序号。
- 通用段在六位制下写作 `400000` / `401000` / `500000`，与第三章的响应示例保持一致。
- 模块之间互不占用号段，新增模块先登记再开发，避免码值冲突。

## 二、枚举组织：公共枚举 + 模块独立枚举

### 2.1 目录结构

```
common
└── enums
    └── CommonResultCodeEnum.java   // 公共错误码 400/401/500 这一类
module-user
└── enums
    └── UserCodeEnum.java           // 用户模块 10xxxx
module-exam
└── enums
    └── ExamCodeEnum.java           // 考试模块 12xxxx
```

统一返回对象 `Result<T>` 放在 `common`，**接收一个接口，而不是固定枚举**。

### 2.2 统一接口

```java
public interface IResultCode {
    Integer getCode();
    String getMsg();
}
```

### 2.3 公共枚举

```java
public enum CommonResultCodeEnum implements IResultCode {
    SUCCESS(200000, "成功"),
    PARAM_ERROR(400000, "参数错误"),
    UNAUTHORIZED(401000, "未登录，请先登录"),
    FORBIDDEN(403000, "无访问权限"),
    NOT_FOUND(404000, "资源不存在"),
    SYSTEM_ERROR(500000, "系统内部错误");

    private final Integer code;
    private final String msg;

    CommonResultCodeEnum(Integer code, String msg) {
        this.code = code;
        this.msg = msg;
    }

    @Override
    public Integer getCode() {
        return code;
    }

    @Override
    public String getMsg() {
        return msg;
    }
}
```

> 若项目已引入 Lombok，可用 `@Getter` + `@AllArgsConstructor` 消除各枚举中重复的构造器和 getter。

### 2.4 模块枚举

```java
public enum UserCodeEnum implements IResultCode {
    USER_NOT_EXIST(100001, "用户不存在"),
    USER_DISABLED(100002, "用户已被禁用");

    // 构造器与 getter 同上
}
```

```java
public enum ExamCodeEnum implements IResultCode {
    EXAM_NOT_EXIST(120001, "考试不存在");

    // 构造器与 getter 同上
}
```

## 三、统一返回体 Result（全局唯一）

> **强制规范**：全局只有这一个 `Result`，所有 Controller 一律返回它。变化的只有 `code` 和 `msg`，外层字段永远不变。

### 3.1 完整定义

```java
public class Result<T> {
    private Integer code;
    private String msg;
    private T data;
    private String traceId;   // 链路追踪 ID，排查问题必备

    // 成功重载
    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(CommonResultCodeEnum.SUCCESS.getCode());
        r.setMsg(CommonResultCodeEnum.SUCCESS.getMsg());
        r.setData(data);
        r.setTraceId(MdcUtil.getTraceId());
        return r;
    }

    // 失败：接收 IResultCode 接口（公共枚举 / 任意模块枚举都能传）
    public static <T> Result<T> fail(IResultCode code) {
        Result<T> r = new Result<>();
        r.setCode(code.getCode());
        r.setMsg(code.getMsg());
        r.setData(null);
        r.setTraceId(MdcUtil.getTraceId());
        return r;
    }

    // 失败：支持自定义提示（少量场景，比如参数校验补充具体信息）
    public static <T> Result<T> fail(IResultCode code, String msg) {
        Result<T> r = new Result<>();
        r.setCode(code.getCode());
        r.setMsg(msg);
        r.setData(null);
        r.setTraceId(MdcUtil.getTraceId());
        return r;
    }

    // getter / setter 省略（Lombok @Data 或手写）
}
```

`traceId` 取自 MDC（`MdcUtil.getTraceId()`），由网关或过滤器在请求入口写入。响应体里的 traceId 与日志里的 traceId 必须是同一个值，前端报错截图即可直接定位到具体日志。

### 3.2 响应示例

不管哪个模块报错，格式一模一样：

```json
{
  "code": 110001,
  "msg": "题目不存在",
  "data": null,
  "traceId": "20261029xxxx"
}
```

```json
{
  "code": 401000,
  "msg": "未登录，请先登录",
  "data": null,
  "traceId": "20261029xxxx"
}
```

### 3.3 强制要点

- `Result` 只有这一个，**所有 Controller 都返回它**
- 变化的只有 `code` 和 `msg`，来源可以是公共枚举 / 各个模块自己的枚举
- 外层字段永远不变：`code / msg / data / traceId`

### 3.4 调用方式

```java
// 成功
return Result.success(userVO);

// 公共错误
return Result.fail(CommonResultCodeEnum.PARAM_ERROR);

// 模块错误
return Result.fail(UserCodeEnum.USER_NOT_EXIST);
return Result.fail(ExamCodeEnum.EXAM_NOT_EXIST);

// 需要补充上下文时
return Result.fail(CommonResultCodeEnum.PARAM_ERROR, "手机号格式不正确");
```

## 四、职责分层：外壳与编码

| 层 | 职责 | 数量 | 是否变化 |
|---|---|---|---|
| `Result<T>` | 统一外壳：`code / msg / data / traceId` | 全局一份 | **永不变化** |
| `IResultCode` + 枚举 | 内部业务编码 | 公共一份 + 各模块各一份 | 随业务扩展 |

一句话分清：

- **`Result`**：统一外壳，全局一份，不变
- **`IResultCode` + 枚举**：里面的业务编码，公共一份 + 各模块自己一份

## 五、落地约束

1. `Result` 只依赖 `IResultCode`，**不得反向依赖任何模块的枚举**，否则 `common` 会被业务模块污染。
2. 业务枚举只在自己的模块内定义与使用，跨模块调用走公共码或各自的 Service 出口。
3. 新增码值只允许在所属模块的枚举末尾追加，**不复用、不修改已发布的码值**，避免前端映射错乱。
4. 同一含义在公共段已有码值时复用，不再于模块段重复定义。
5. `traceId` 必须在**请求入口**写入 MDC，且响应体、日志、下游调用三处取同一个值，否则失去排查价值。
6. 成功响应也走 `Result.success()`，**不允许**手写 `{"code":200,"msg":"ok"}` 之类的临时结构。

## 六、新增模块接入步骤

1. 在上方「错误码分段登记」表里申请一个新段位（如 `14xxxx`）。
2. 在该模块 `enums` 包下新建 `XxxCodeEnum implements IResultCode`。
3. 按同一模板补齐构造器与 getter，码值从段位起点递增。
4. 返回时统一走 `Result.fail(XxxCodeEnum.YYY)`。
