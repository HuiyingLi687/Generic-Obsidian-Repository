## 0\.全局通用约定

1. 返回统一包装：全部返回 `Result<T>`，HTTP 状态码固定 200，业务看 code

```json
{ "code": 200, "message": "操作成功", "data": {} }
```

1. 鉴权规则

- 所有接口必须登录，未登录返回 401

- userId **必须从 token 解析获取，禁止前端传入**

- 请求头：`Authorization: Bearer xxx`、`X-Client-Type: APP`

1. ID 序列化：雪花 Long ID，前端接收使用字符串，避免 JS 精度丢失

2. 时间：全部返回毫秒时间戳

3. 分页：pageNum 默认 1，pageSize 默认 10，最大 100，超限返回 400

4. 兼容性：新增字段全部允许为 null，老版本客户端无需升级

5. RPC 调用约定：内部 http 调用超时时间 1500ms，超时采用 fail\-closed 策略，直接返回 500，不允许放行业务

## 2\.业务决策/核心公式

> 【示范，正式文档删除并替换】产品确定的业务规则、阈值、计算公式，不要只放在代码注释
> 
> 

- 规则1：新用户注册，每个科目初始打卡剩余次数 = 1 次

- 规则2：每成功邀请 1 位用户，每个科目次数 \+1

- 规则3：单人有效邀请上限最多 2 人

- 公式：

```
remain_quota = 注册赠送次数 + min(有效邀请人数,2) - 该科目已使用次数
单科上限 = 3
```

## 5\.接口详细定义

### POST /api/clock/in

**用途**：用户提交科目打卡
**鉴权**：需要登录

**入参说明**

> 参数位置：path / query / header / body
> 
> 

|参数名|位置|类型|必填|约束\&说明|
|---|---|---|---|---|
|subjectType|body|String|是|科目编码，只能是 arts\_chinese/science\_chinese/math/physics/chemistry|
|clockDate|body|Long|是|打卡日期毫秒时间戳|

**请求示例**

```json
{
  "subjectType":"math",
  "clockDate": 1760880320000
}
```

**返回成功示例**

```json
{
  "code":200,
  "message":"打卡成功",
  "data":{
    "clockRecordId": "1234567890123456789"
  }
}
```

**返回字段说明**

|字段|类型|说明|
|---|---|---|
|clockRecordId|String|打卡记录主键 ID|

**服务端内部执行顺序（重要，后端\&测试阅读）**

> 简单单表 CRUD 可简写；存在事务 / RPC / 多分支 / 并发，必须逐条完整写清步骤、分支走向、事务边界、禁止行为。
> 
> 

1. 请求参数校验：subjectType 在科目白名单、clockDate 时间合法；校验失败返回 400

2. 从 token 解析 userId，获取用户 id

3. 查询该用户该科目的配额记录，校验 `remain_quota > 0`；次数不足返回业务错误码 8105

4. 开启 `@Transactional(rollbackFor = Exception.class)` 本地事务

    1. 调用 domain 领域层执行业务规则校验：判断今日是否已经打卡，重复打卡抛出业务异常

    2. 扣减该科目剩余次数，使用行锁更新，where 条件带上 id and remain\_quota\>0，防止超扣

    3. 插入一条打卡记录

5. 事务提交成功之后，发送 MQ 打卡成功事件，用于统计、消息通知；MQ 发送异常只打 error 日志，不回滚主业务

6. 返回打卡记录 ID

> 约束重点
> 
> 1. 打卡业务校验逻辑放在 domain 领域类，domain 不注入 mapper，数据全部上层传入
> 
> 2. 扣减次数必须按主键 id 行更新，禁止全用户条件更新，避免误扣其他科目次数
> 
> 3. MQ 发送在事务提交之后，不能放在事务内部
> 
> 

**本接口抛出错误码**：400 / 401 / 8105

### GET /api/clock/quota

**用途**：查询用户 5 个科目剩余打卡次数
**鉴权**：需要登录

**入参说明**：无，userId 从 token 获取

**返回成功示例**

```json
{
  "code": 200,
  "message": "查询成功",
  "data": {
    "quotas": [
      { "subjectType": "math", "subjectTypeText": "数学", "totalQuota": 3, "usedQuota": 1, "remainQuota": 2, "hasQuota": true }
    ],
    "totalRemainQuota": 10
  }
}
```

**服务端内部执行顺序（重要，后端\&测试阅读）**

1. 解析 token 拿到 userId

2. 批量查询该用户全部 CSCA 科目配额记录

3. 使用固定常量列表组装 5 个科目返回结果，缺行自动填充 0；禁止依赖枚举 values\(\) 遍历顺序

4. 组装返回对象直接返回，只读无写库操作，无事务

**本接口抛出错误码**：401

## 7\.边界特殊场景说明

> 并发、重复请求、空数据、外部调用超时策略（fail\-closed / fail\-open）
> 
> 

1. 并发打卡：扣减次数使用行锁 `where id=? and remain_quota>0`，防止并发下超扣次数

2. 重复提交同一个打卡日期：domain 层做重复打卡校验直接拦截

3. MQ 发送失败：只记录 error 日志，不影响打卡主流程，不回滚事务
