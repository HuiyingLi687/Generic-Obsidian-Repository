### GET /api/auth/app/invitation/getCode

**用途**：获取用户邀请码与奖励进度
**鉴权**：需要登录

**入参说明**

|参数名|位置|类型|必填|约束\&说明|
|---|---|---|---|---|
|examType|query|String|是|【修改】增加白名单限制，仅允许 `HSK/HSKK/CSCA`，其它值返回 400|
|X\-Client\-Type|header|String|否|【无变更】|

**请求示例**

```http
GET /api/auth/app/invitation/getCode?examType=CSCA
Authorization: Bearer xxx
X-Client-Type: APP
```

**返回完整示例**

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "invitationCode": "BDDSC",
    "examType": "CSCA",
    "rewardedCount": 0,
    "rewardLimit": 2,
    "remainRewardCount": 2,
    "rewardPerInvite": 1,
    "rewardSubjectCount": 5,
    "isMax": false
  }
}
```

**返回字段说明**

|字段|类型|改动标记|说明|
|---|---|---|---|
|invitationCode|String|【无变更】|5 位邀请码|
|examType|String|【无变更】|归一大写考试类型|
|rewardedCount|Integer|【无变更】|已发放奖励次数|
|rewardLimit|Integer|【无变更】|邀请上限|
|remainRewardCount|Integer|【新增】|剩余可邀请人数 = rewardLimit \- rewardedCount|
|rewardPerInvite|Integer|【新增】|单次邀请每个科目奖励次数，恒为 1|
|rewardSubjectCount|Integer|【新增】|奖励覆盖科目数量，CSCA=5，HSK/HSKK=1|
|isMax|Boolean|【无变更】|是否达到邀请上限|

**服务端内部执行顺序（重要，后端\&测试阅读）**

1. 校验登录鉴权头部

2. examType 白名单校验，不在白名单直接返回 400

3. 查询/懒生成用户对应 examType 邀请码

4. 组装全部返回字段，填充新增输出字段

> 约束：每个用户\+每个 examType 只生成一条邀请码，码长期不变
> 
> 

**本接口抛出错误码**：400 / 401

### POST /api/auth/app/register（邮箱注册）

**用途**：邮箱注册账号并处理邀请码绑定逻辑
**鉴权**：无需登录

**入参说明**

|参数名|位置|类型|必填|约束\&说明|
|---|---|---|---|---|
|email|body|String|是|【无变更】账号邮箱|
|password|body|String|是|【无变更】密码|
|invitationCode|body|String|否|【无变更】可选邀请码|

**请求示例**

```json
{
  "email": "test@demo.com",
  "password": "xxxxxx",
  "invitationCode": "BDDSC"
}
```

**返回完整示例**

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "userId": "100001",
    "token": "xxxxxx"
  }
}
```

**返回字段说明**：全部【无变更】，本次迭代返回结构无改动

**服务端内部执行顺序（重要，后端\&测试阅读）**

1. 账号参数校验，账号已存在返回 400

2. 插入 user 用户记录

3. 【新增逻辑】初始化考试配额，除 HSK、HSKK 之外新增插入 CSCA 5 条初始配额

4. 执行 handleInvitationOnRegister 邀请绑定逻辑，增加 `@Transactional(rollbackFor = Exception.class)`

    - 过滤：空邀请码、注销历史用户、自己邀请自己、已经存在绑定记录直接跳过

    - 插入绑定记录，reward\_status=0

    - 顺序约束：**先发放考试配额次数，再更新 rewardedCount 计数，顺序不能颠倒**

    - 发放失败设置 reward\_status=3；捕获异常后注册流程仍正常返回成功，注册不能因邀请奖励失败而失败

5. 返回注册成功结果

**本接口抛出错误码**：400 / 500

## 6\.前端对接注意事项

1. 新增返回字段允许为 null，老 App 忽略即可，不需要强制升级

2. reward\_status=3 页面展示文案：发放失败，已记录

## 7\.关键业务流程\&事务边界

handleInvitationOnRegister 执行要点：

1. 方法增加 `@Transactional(rollbackFor = Exception.class)`

2. 先发放配额次数，后更新 rewardedCount 计数，顺序不能颠倒

3. 捕获业务异常设置 reward\_status=3，注册流程正常返回成功，不能让注册失败
