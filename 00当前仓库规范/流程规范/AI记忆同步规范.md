# AI 记忆同步规范

> 解决的问题：AI 的记忆存在本机 `.workbuddy/memory/`，换机器、换会话就看不见；项目知识库在 Obsidian，两边各写一半，必然对不上。
> **本文件规定：哪些记忆必须进 Obsidian、进哪一篇、什么时候写。**
>
> 与 [Obsidian管理规范](Obsidian管理规范.md) 的分工：那份管「目录怎么建、文件怎么命名」，这份管「AI 的结论往哪落、什么时候落」。

## 一、三层分工

| 层 | 放哪 | 存什么 | 生命周期 |
|---|---|---|---|
| **索引层** | `.workbuddy/memory/MEMORY.md`（本机） | **只有指针**：先读哪两篇 + 少数几条每次都用的铁律 | 长期，≤ 40 行 |
| **正文层** | Obsidian `<项目>/`（本仓库） | 结论、字段口径、机制、决策、实证数据 | 长期，跨机器 |
| **流水层** | `.workbuddy/memory/YYYY-MM-DD.md`（本机） | 过程：试了什么、报了什么错、跑过什么命令 | 30 天后可删 |

判据一句话：

> **「三个月后还要不要看？」要 → 正文层；只是「当时怎么试出来的」→ 流水层。**

## 二、落点映射（按「回答哪个问题」归属，不按内容类型）

| 记忆内容 | 必须写进 |
|---|---|
| 现在做到哪、下一步、不能碰什么 | `<项目>/00当前进度/当前进度.md` |
| 改了表 / 加了列 / 回填了数据 | `<项目>/00当前进度/00数据库变更台账/<序号>-YYYY-MM.md` |
| 字段的脾气：类型、取值域、为空率、踩过的具体后果 | `<项目>/02软件架构/03数据字典/00字段红线索引.md` |
| 跨模块机制：取卷、判分、事务、鉴权 | `<项目>/02软件架构/04关键算法/` |
| 数据实证：分布统计、脏数据普查结论 | 字段级 → 字段红线索引；表级 → 对应模块文档的「实测」小节 |
| 接口字段、页面结构、模块方案 | `<项目>/03业务模块/<模块>/` |
| 为什么当初这么定、否决了什么 | `<项目>/README.md`「关键决策」；超过 5 条再建 `04决策记录/` |
| 编译、端口、连库、本机工具坑 | `<项目>/00当前进度/01开发环境与命令.md` |
| 需求与状态 | `<项目>/01功能需求/00需求索引.md` |
| 过程流水、试错、命令回显 | 只进本地 `YYYY-MM-DD.md`，**不进 Obsidian** |

## 三、三条硬纪律

1. **当次写，不攒。**
   会话里一旦得出「结论型」事实（字段值域、某字段其实不存在、某段代码的坑、数据统计），当场写进上表对应文件，并更新该文件 frontmatter 的 `updated`。
2. **一次会话 = `当前进度.md` 的一行。**
   多条合并成一行，不复述细节，细节链接出去。
3. **写入前先查重。**
   同一结论已在文档里 → 改那一行，不要追加第二遍。数字变了就改数字（例：「71 条占位」→「76 条」）。

## 四、索引层（MEMORY.md）怎么写

只允许三类内容，总长 ≤ 40 行：

1. **读取顺序** —— 先读哪两篇（两屏元信息）
2. **铁律** —— 不超过 5 条，必须是「不知道就会写错」的，每条一句话
3. **指针表** —— 「想知道 X 去读 Y」

禁止写进索引：结论正文、待办清单、「今天做了什么」。

## 五、什么不要进 Obsidian

| 内容 | 原因 |
|---|---|
| 每日流水、命令回显、报错堆栈 | 噪音，检索时全是干扰；留本地 |
| 未验证的猜测 | 会被后来的会话当成事实引用 |
| 一次性的临时路径（`tmp/xxx.py`） | 脚本会删，文档里的链接会烂 |
| 数据库账号密码 | 即使内网也不进 git |
| 超过 10 MB 的备份 / sql 导出 | 违反仓库体积红线 |

## 六、同步自查（每次会话结束）

- [ ] 本次得出的结论，是否已写进 §二 对应文件？
- [ ] 写的是「结论」还是「过程」？过程别写进来
- [ ] 文件头 `updated` 改了吗？
- [ ] 同一结论是否在两处重复？
- [ ] `当前进度.md` 是否加了今天这一行？
